## AI Agent·개발 도구

### Claude Ship, PR 검토·수정·정책 기반 승인을 하나의 흐름으로 연결

Anthropic이 beta로 공개한 Claude Ship은 GA인 Code Review에 PR Steward와 Claude Approvals를 더합니다. Steward는 CI 실패·merge conflict·review feedback을 수정하되 승인·merge는 하지 않고, Approvals는 repository 안의 자연어 정책 파일을 기준으로 자동 승인 또는 사람 승인을 요구합니다. Claude Code의 `/ship`으로 push와 PR 생성부터 이 흐름을 시작할 수 있습니다.

- **중요한 이유:** coding agent가 작성한 변경의 후속 단계도 자동화되지만, agent가 만든 코드를 agent가 승인하는 권한 집중 위험이 있습니다. observe-only, branch protection, spend limit, 민감 경로의 인간 CODEOWNER를 함께 적용해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [Anthropic](https://claude.com/resources/articles/introducing-claude-ship)

### GLM-5.4, 반복 계산 구조를 넣은 coding model 공개

Z.ai는 GLM-5.4를 첫 Loop Transformer 기반 generalized coding model로 소개했습니다. 같은 block을 반복 적용해 계산 깊이를 늘리는 구조를 채택했으며, 공개된 model card와 benchmark는 coding·agent 작업 개선을 주장합니다.

- **중요한 이유:** 긴 coding task에서 반복 추론을 model 구조에 넣는 접근은 비용·latency·정확도의 새 trade-off를 만듭니다. 공급자 benchmark만으로 교체하지 말고 실제 repository의 build 성공률, tool-call 오류, token·wall-clock 비용을 함께 비교해야 합니다.
- **발표일:** 2026-11-23 KST
- **원문:** [Z.ai](https://z.ai/blog/glm-5.4)

- **중요한 이유:** 상담 품질·규정 준수 점수가 model upgrade 때문에 갑자기 바뀌는 위험을 줄입니다. 대표 표본, 언어·상담 유형별 회귀 기준과 human adjudication을 마련해야 합니다.

## 보안·플랫폼

### OpenAI·Cisco, patch 전 Linux를 보호하는 open-source runtime Shirudo 공개

Shirudo는 eBPF shield를 running Linux process에 적용해 재시작 없이 취약 code path를 임시 차단하는 runtime입니다. operator가 영향도를 관찰한 뒤 승인하며, shield 서명·eBPF verifier·TPM 기반 변경 증거를 사용합니다. 양사는 Codex가 만든 shield가 Elasticsearch의 Java4Shell 공격 입력을 막은 controlled test를 제시했습니다.

- **중요한 이유:** 긴급 patch의 검증·재시작 전 노출 시간을 줄이는 보완책이지만 patch 자체를 대체하지 않습니다. generated shield의 false positive, kernel·architecture 호환성, 서명 key와 rollback을 production runbook으로 검증해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [OpenAI](https://openai.com/index/introducing-shirudo)

### AWS WAF, LLM·MCP·A2A endpoint 자동 발견과 Guardrails 검사 GA

API Gateway API Portal이 traffic log와 service configuration에서 LLM, MCP, A2A endpoint를 찾아 public shadow MCP server까지 표시합니다. 새 AI Security managed rule group은 malformed protocol을 차단하고, 선택적 content inspection에서 Bedrock Guardrails로 prompt injection·jailbreak·harmful content와 response의 민감정보를 검사합니다.

- **중요한 이유:** agent endpoint inventory와 protocol 검사를 중앙화할 수 있지만 지원 region이 제한되고 content inspection은 별도 비용이 듭니다. 암호화 payload·streaming·custom transport의 blind spot, false positive와 개인정보의 Guardrails 전달 범위를 확인해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/)

### Amazon Inspector, ECR·EC2 취약점에 runtime reachability 신호 추가

Inspector가 ECR image에서는 `WORKDIR`·`ENTRYPOINT`·`CMD` 경로, EC2에서는 최근 scan에서 실제 process로 관측된 package를 바탕으로 취약 package의 잠재적 도달 가능성을 표시합니다. EC2 분석에는 Inspector VM Scanner 기반 agent scan이 필요하며 신규 finding부터 적용되고 기존 finding은 순차 backfill됩니다.

- **중요한 이유:** 사용되지 않는 dependency와 실행 중인 취약 code를 구분해 patch 우선순위를 개선합니다. ‘관측되지 않음’은 안전함의 증명이 아니므로 internet exposure·EPSS/CVSS·asset 중요도와 함께 판단해야 합니다.
- **발표일:** 2026-11-23 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/inspector-runtime-reachability/)

## 웹·클라우드·데이터·인프라

### AWS WAF, rule 수 대신 보호 resource·traffic·보호 수준 중심 요금제로 전환

새 요금은 protected resource, 검사 request, advanced protection이 평가한 request의 세 축으로 계산합니다. web ACL당 추가 요금 없는 WCU가 1,500에서 2,500으로 늘고 일반 rule 변경은 rate를 바꾸지 않지만 Bot Control targeted, Fraud Control, API Security, AI Security에는 premium request fee가 붙습니다.

- **중요한 이유:** configuration 변경의 비용 예측은 쉬워지지만 고트래픽 login·checkout API에 advanced rule을 적용하면 비용 구조가 달라집니다. 기존 bill을 새 세 축으로 replay하고 CDN cache hit·bot traffic까지 포함해 비교해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-waf-introduces-simplified-pricing/)

### Global Accelerator, TLS listener NLB에도 원본 client IP 보존

Global Accelerator가 TLS를 NLB에서 종료하면서도 application에 실제 client IP를 전달할 수 있게 됐습니다. 이전에는 NLB TLS termination과 client IP preservation 중 하나를 선택해야 했으며, 이제 security group·geo-blocking·rate limit·fraud detection과 audit에 원본 IP를 사용할 수 있습니다.

- **중요한 이유:** non-HTTP 결제 protocol이나 고처리량 TCP service에서 static IP와 TLS termination, 원본 IP 정책을 함께 쓸 수 있습니다. proxy chain·IPv6, allowlist와 log schema가 바뀌지 않는지 canary로 확인해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/global-accelerator-client-ip-nlb-tls/)

### Aurora Serverless v2 for MySQL, 최대 384 ACU까지 확장

Aurora Serverless for MySQL의 instance당 최대 용량이 384 Aurora Capacity Units로 늘었습니다. burst가 큰 database를 serverless scaling 범위 안에서 더 크게 운영할 수 있는 선택지입니다.

- **중요한 이유:** 대형 주문·campaign spike를 처리할 headroom은 커지지만 scale-up 속도와 connection pool, query bottleneck이 자동으로 해결되는 것은 아닙니다. max ACU 비용 한도, replica 배치와 부하시험을 함께 조정해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-serverless-mysql-supports-384-acu/)

### Ladybird, 독자 browser engine의 macOS·Linux alpha 배포

Ladybird가 fork가 아닌 자체 engine으로 만든 browser의 rolling alpha를 공개했습니다. WebDriver와 Firefox DevTools protocol을 지원해 web compatibility test가 가능하지만, project는 현재 보안을 보장하지 않으며 취약점 제보를 적극 요청했습니다.

- **중요한 이유:** Chromium·WebKit·Gecko 밖의 engine 다양성이 생기지만 사용자용 안정 browser로 간주할 단계는 아닙니다. 개발자는 별도 test target으로만 추가하고 rendering·accessibility·security 차이를 report하는 것이 적절합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [Ladybird](https://ladybird.org/posts/alpha/)

### Stalwart, Microsoft Exchange 호환 mail·calendar server 방향 공개

Stalwart Labs는 기존 Outlook·mobile client가 연결할 수 있는 Exchange-compatible self-hosted server를 목표로 mail, calendar, contacts와 관리 기능을 통합하는 계획을 발표했습니다. 공개 구현을 통해 proprietary groupware 의존을 줄이려는 접근입니다.

- **중요한 이유:** migration 선택지는 늘지만 ‘drop-in’ 주장은 조직별 Exchange protocol·Outlook add-in·compliance·retention 호환성을 보장하지 않습니다. test tenant에서 mailbox 이동, calendar edge case, backup·legal hold와 mobile policy를 검증해야 합니다.
