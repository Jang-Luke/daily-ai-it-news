# 2026-11-20 AI·IT 개발 뉴스

최근 24시간의 공식 발표와 릴리스를 우선했습니다. 서비스 공급자의 성능 수치는 독립 검증 결과와 구분했으며, preview·canary 기능은 운영 안정판으로 간주하지 않았습니다.

## AI Agent·개발 도구

### GitHub CLI, pull request event 대기 기능 지원

GitHub CLI v2.105.0이 GitHub Event Streams를 이용해 pull request 상태 변화를 polling 없이 기다릴 수 있게 됐습니다. 개발자와 coding agent는 반복 API 호출 대신 event-driven 방식으로 review·merge·check 변화를 감지할 수 있습니다.

- **중요한 이유:** CI와 agent workflow의 API 호출량과 지연을 줄일 수 있지만, 연결 중단·event 유실에 대비한 timeout과 최종 상태 재조회가 필요합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-18-wait-for-pull-request-events-with-github-cli)

### GitHub, Azure DevOps Enterprise Live Migrations 일반 제공

Azure DevOps Services에서 data residency가 적용된 GitHub Enterprise Cloud로 repository를 옮기는 Enterprise Live Migrations가 일반 제공됐습니다. 팀이 기존 repository에서 작업을 계속하는 동안 복제한 뒤 짧은 전환 구간을 두는 방식입니다.

- **중요한 이유:** 대규모 이전의 업무 중단을 줄이지만 identity·permission·branch policy·CI secret과 migration 직후 delta 검증은 별도 계획이 필요합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-19-enterprise-live-migrations-from-azure-devops-generally-available)

### GitHub-hosted larger runner에 RHEL 9·10 일반 제공

GitHub Actions의 larger runner에서 Red Hat Enterprise Linux 9와 10 image가 public preview를 마치고 일반 제공됐습니다. 기업은 RHEL 기반 build·test를 GitHub-hosted 환경에서 수행할 수 있습니다.

- **중요한 이유:** production RHEL과 CI의 OS 차이를 줄일 수 있지만 image update 주기, package repository와 runner 비용을 고정된 self-hosted 환경과 비교해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-19-red-hat-enterprise-linux-runner-images-now-generally-available)

### Amazon Connect Resolutions, agent와 결정론적 workflow 결합

AWS가 환불, 거래 분쟁, 사기 조사와 보험 청구 같은 대량 업무를 agent reasoning과 결정론적 workflow로 처리하는 Resolutions를 일반 제공했습니다. 자연어 또는 SOP에서 work plan을 만들고 사람의 감독과 검증 가능한 결과를 결합한다고 AWS는 설명합니다.

- **중요한 이유:** 주문 취소·환불 자동화 범위가 넓어지지만 금액 한도, 승인 단계, 근거 기록과 사람에게 이관하는 실패 조건을 명시해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-connect-resolutions/)

## 보안·클라우드·플랫폼

### GHE.com, OIDC 기반 S3 audit log streaming 지원

Data residency가 적용된 GitHub Enterprise Cloud에서도 OIDC를 사용해 enterprise audit log를 Amazon S3로 streaming할 수 있게 됐습니다. 장기 access key 없이 short-lived credential을 발급하는 기존 github.com 기능이 GHE.com으로 확장됐습니다.

- **중요한 이유:** 정적 AWS credential 노출 위험을 줄이지만 trust policy의 organization·enterprise 조건, S3 write 권한과 log 무결성·보존 설정을 검토해야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-19-s3-audit-log-streaming-with-openid-connect-expands-to-ghe-com)

### Cognito app client secret, Secrets Manager에서 관리

Amazon Cognito가 user pool app client secret을 AWS Secrets Manager에 저장·관리하도록 통합했습니다. IAM policy, KMS 암호화와 rotation 기능을 활용할 수 있어 Cognito에 직접 보관·교체하던 절차를 표준 secret lifecycle에 넣을 수 있습니다.

- **중요한 이유:** 인증 secret rotation을 중앙화할 수 있지만 배포 중 old/new secret overlap, cache와 rollback 동작을 실제 client에서 시험해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-secrets-manager-integration/)

### Route 53, private endpoint health check 지원

Route 53이 public internet에 노출되지 않은 internal API, database, private subnet endpoint를 HTTP·HTTPS·TCP로 확인하고 private hosted zone DNS failover에 연결할 수 있게 했습니다. 기존 custom health-check control loop를 managed 기능으로 대체할 선택지가 생겼습니다.

- **중요한 이유:** 내부 서비스 failover가 단순해지지만 health probe 경로 자체의 network reachability와 application-level 정상성, DNS TTL을 함께 검증해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/route-53-private-endpoint-health-checks/)

### Lambda durable functions, OpenTelemetry tracing 지원

Lambda durable functions가 여러 invocation에 걸쳐 suspend·resume되는 전체 실행을 하나의 OpenTelemetry trace로 내보낼 수 있게 됐습니다. CloudWatch뿐 아니라 표준 OTel backend에서 장시간 workflow 병목과 실패를 추적할 수 있습니다.

- **중요한 이유:** agent와 결제 workflow의 재시도·checkpoint를 end-to-end로 관찰할 수 있지만 trace에 개인정보나 결제 payload가 들어가지 않도록 attribute 정책이 필요합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/lambda-durable-otel/)

### Lambda on-demand Event Functions timeout, 30분으로 확대

AWS Lambda on-demand Event Functions의 synchronous·asynchronous·event source mapping invocation 최대 시간이 15분에서 30분으로 늘었습니다. AI inference, media 처리와 긴 계산을 재설계 없이 옮길 여지가 커졌습니다.

- **중요한 이유:** 긴 작업의 운영 선택지가 늘지만 timeout 연장은 비용·재시도 중복·lock 유지 위험도 키우므로 idempotency와 progress checkpoint가 필요합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-30-minute-ondemand-event-functions/)

### CloudFront SaaS Manager, IP 기반 routing과 connection log 추가

CloudFront SaaS Manager가 같은 wildcard domain 아래 tenant를 전용 Anycast static IP 또는 shared IP로 구분해 configuration에 routing하고 viewer connection log를 제공하기 시작했습니다. premium tenant 분리와 연결 수준 진단에 활용할 수 있습니다.

- **중요한 이유:** multi-tenant CDN의 등급 분리가 쉬워지지만 domain·IP mapping 오류, tenant isolation과 connection log의 개인정보 처리가 새로운 운영 책임입니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/cloudfront-ip-based-routing-connection-logging)

## 데이터베이스·데이터

### Aurora DSQL, write throughput 최대 50% 향상 발표

AWS는 storage layer 개선으로 Aurora DSQL의 많은 transactional workload에서 write throughput이 최대 50% 높아졌다고 발표했습니다. timestamp·identity·ULID·UUIDv7처럼 증가하는 primary key의 write-heavy table은 AWS 내부 시험에서 더 큰 개선을 보였다고 설명합니다.

- **중요한 이유:** ledger·event feed·주문 event 저장 비용을 낮출 가능성이 있지만 공급자 benchmark이므로 실제 schema와 contention 패턴으로 재측정해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-dsql-higher-write-throughput/)

### Aurora DSQL, 대륙 간 multi-Region cluster 지원

Aurora DSQL이 미국 동부와 유럽처럼 서로 다른 대륙의 두 region을 하나의 strongly consistent multi-Region cluster로 구성할 수 있게 했습니다. 한 region 장애 때 committed write를 보존하고 다른 region에서 읽기·쓰기를 계속하도록 설계됐습니다.

- **중요한 이유:** 글로벌 서비스의 데이터 일관성과 장애 격리를 강화하지만 intercontinental write latency, data residency와 network partition 시 동작을 부하 시험해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-dsql-intercontinental-multi-region-clusters/)

### Aurora cluster, data migration 없이 다른 VPC로 이동

Aurora PostgreSQL과 MySQL cluster를 새 cluster와 data migration 없이 단일 modify 작업으로 다른 VPC에 옮길 수 있게 됐습니다. IP 공간 부족, overlapping CIDR 해소와 network architecture 통합에 활용할 수 있습니다.

- **중요한 이유:** network 재편의 복잡도를 낮추지만 endpoint·security group·DNS·connection pool과 전환 중 가용성을 staging에서 확인해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-move-clusters-to-different-vpc/)

### MSK Connect, connector와 task의 in-place restart 지원

Amazon MSK Connect가 connector 전체 또는 실패한 task만 삭제·재생성 없이 다시 시작하는 기능을 지원합니다. Kafka Connect pipeline 장애 복구에서 configuration 재작성과 불필요한 downtime을 줄일 수 있습니다.

- **중요한 이유:** 운영 복구는 빨라지지만 source offset, sink idempotency와 restart 뒤 중복 처리 여부를 connector별로 확인해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-msk-connect-restart-existing-connectors)
