## AI Agent·개발 도구

### Google, transformer residual connection을 위한 DeepCrossAttention 공개

Google Research는 residual connection을 개선하는 DeepCrossAttention이 비교 가능한 model 품질을 최대 3배 빠르게 달성했다고 발표했습니다. 연구 결과는 특정 학습 조건의 성능 비교이며 모든 model·workload에서 같은 향상을 보장하는 것은 아닙니다.

- **중요한 이유:** 대규모 model 학습에서 residual 경로 변경은 수렴 속도와 compute 비용에 직접 영향을 줍니다. 적용 전 기존 architecture 대비 loss curve, memory 사용량과 downstream 품질을 동일 조건에서 재현해야 합니다.
- **발표일:** 2026-11-28 KST
- **원문:** [Google Research](https://research.google/blog/supercharging-transformer-residual-connections/)

### Amazon Neptune Graph Sessions 정식 제공

AWS는 agent·사용자·task별 작은 graph를 만들고 idle 15분 뒤 scale-to-zero하는 Neptune Graph Sessions를 출시했습니다. 4 또는 8 s-NCU에서 시작하고 graph data를 유지한 채 수초 안에 재개하며 openCypher로 질의합니다.

- **중요한 이유:** GraphRAG와 per-session knowledge graph를 provisioned graph 하나에 섞지 않고 격리할 수 있습니다. 다만 재개 지연, session 수 증가에 따른 비용, tenant별 data 삭제 수명주기를 실제 traffic으로 검증해야 합니다.
- **발표일:** 2026-11-28 KST

## 데이터베이스·클라우드·인프라

### Timestream for InfluxDB 3, heterogeneous cluster 지원

AWS는 InfluxDB 3 Enterprise cluster에서 writer, reader, compactor node role마다 서로 다른 instance size를 지정할 수 있게 했습니다. query cache에는 memory, write에는 durable flush, compaction에는 CPU가 필요한 비대칭 workload를 독립 확장할 수 있습니다.

- **중요한 이유:** 전체 cluster를 가장 무거운 role에 맞춰 overprovision하지 않아도 됩니다. 변경 전 role별 CPU·memory·I/O 병목을 측정하고 compaction backlog와 query p99를 함께 관찰해야 비용 절감이 성능 저하로 바뀌지 않습니다.
- **발표일:** 2026-11-28 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/influxdb-heterogeneous-cluster/)

### CloudWatch, 기본 OpenTelemetry enrichment 무료 제공

AWS service metric을 OpenTelemetry data point로 바꿔 PromQL로 질의하는 기본 enrichment가 추가 비용 없이 제공됩니다. ARN, cloud provider, Region, account ID와 source service가 resource attribute로 붙고 기존 dimension은 data point attribute가 됩니다.

- **중요한 이유:** AWS native metric과 application OTel metric을 같은 query model로 다루기 쉬워집니다. resource tag를 label로 붙이는 별도 유료 enrichment와 cardinality·비용 차이를 구분해 설정해야 합니다.
- **발표일:** 2026-11-28 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudwatch-opentelemetry-enrichment/)

## 웹·언어·프레임워크

### Rust 1.100.1, Iterator 구현 추론 regression 수정

Rust 1.100.1은 unstable const `Iterator` 변경이 기존 유효한 구현을 `Iterator`로 인식하지 못하게 만든 regression을 되돌린 patch release입니다. 영향을 받은 build는 compiler update만으로 복구될 수 있지만 project별 재검증이 필요합니다.

- **중요한 이유:** patch compiler도 type inference와 trait resolution 결과를 바꿀 수 있습니다. workspace 전체 test, MSRV 정책과 generated code를 확인한 뒤 toolchain pin을 갱신해야 합니다.
- **발표일:** 2026-11-28 KST
- **원문:** [Rust 공식 release](https://github.com/rust-lang/rust/releases/tag/1.100.1)

### workerd v1.20261127.1 배포

Cloudflare의 open-source Workers runtime release에는 V8 15.9.128.39 update, User Timing spec 오류 정합성, SubtleCrypto의 SharedArrayBuffer-backed view 거부, MIME parsing의 Rust 이동 등이 포함됐습니다. 일부 Rust 전환은 autogate 뒤에 있어 즉시 모든 deployment에 적용된다고 단정할 수 없습니다.

- **중요한 이유:** Workers 호환 runtime과 edge application은 crypto input, console label coercion, SQLite VFS와 performance timing 동작을 회귀시험해야 합니다. V8 update가 native addon 없이도 JavaScript semantics와 memory profile에 미치는 영향도 관찰해야 합니다.
- **발표일:** 2026-11-27 KST
- **원문:** [공식 release](https://github.com/cloudflare/workerd/releases/tag/v1.20261127.1)

### Next.js v16.5.0-canary.70, Turbopack image import 수정

Next.js canary.70은 `node_modules`에서 import한 image가 Turbopack에서 `StaticImageData`를 반환하도록 수정하고 dev server link inspection 등을 반영했습니다. canary channel이므로 production 권장 stable release는 아닙니다.

- **중요한 이유:** component library가 image를 export하는 monorepo에서 bundler별 type·runtime 차이를 줄일 수 있습니다. stable 반영 전에는 webpack·Turbopack 양쪽 build와 SSR output을 비교해야 합니다.
- **발표일:** 2026-11-27 KST
- **원문:** [공식 release](https://github.com/vercel/next.js/releases/tag/v16.5.0-canary.70)
