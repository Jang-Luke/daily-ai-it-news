# 2026-11-21 AI·IT 개발 뉴스

최근 24시간의 공식 발표와 릴리스를 우선해 중복 사건을 합쳤습니다. preview·release candidate와 공급자 성능 수치는 안정판 또는 독립 검증 결과와 구분했습니다.

## AI Agent·개발 도구

### AWS Quick, 기업용 프롬프트 가드레일 preview

AWS Quick가 사용자·IdP 그룹·계정 기본값별로 content filter, 금지 주제·단어, prompt-attack 탐지와 일부 PII 제어를 설정하는 enterprise guardrails를 preview로 공개했습니다. 탐지만 수행해 CloudWatch Logs로 영향을 살핀 뒤 차단을 적용할 수 있고, 여러 그룹 정책이 겹치면 더 엄격한 제한을 사용합니다.

- **중요한 이유:** 사내 AI 도구에 정책을 중앙 적용할 수 있지만 preview 범위, 오탐, 로그의 민감정보와 우회 입력을 실제 업무 트래픽으로 검증해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-quick-enterprise-guardrails-preview/)

### GitHub Desktop 3.7.0, host별 다중 계정 지원

GitHub Desktop이 GitHub.com, GHES, GHE.com의 같은 host에 계정을 여러 개 등록하고 repository마다 사용할 계정을 연결할 수 있게 됐습니다. clone·publish·Git 작업은 연결된 credential을 자동 사용하며 기존 repository는 현재 계정으로 migration됩니다.

- **중요한 이유:** 개인·회사 계정 혼용 실수를 줄이지만 조직 SSO, commit identity와 signing key까지 자동 분리되는 것은 아니므로 별도 정책 점검이 필요합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-19-github-desktop-now-supports-multiple-accounts-per-host)

### GitHub pull request Overview preview 개선

새 PR Overview가 optional check 실패를 merge 차단처럼 보이지 않게 하고, 누락된 요구사항과 다음 행동을 더 명확히 표시합니다. resolved thread 접기, force-push 전후 commit 링크, commit timestamp와 작은 화면의 branch 표시도 개선됐습니다.

- **중요한 이유:** reviewer와 coding agent가 merge 가능성을 더 정확히 판단할 수 있지만 public preview이므로 자동화는 UI 문구가 아니라 API의 required checks·review 상태를 기준으로 해야 합니다.
- **발표일:** 2026-11-20 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-19-improvements-on-the-pull-request-overview-in-public-preview)

### GitHub dashboard에 favorite repository 고정

GitHub의 새 dashboard 경험에서 원하는 repository를 Favorite repositories 영역에 직접 고정할 수 있게 됐습니다. 새 dashboard를 사용하지 않는 계정의 Top repositories 동작은 바뀌지 않습니다.

- **중요한 이유:** 다수 repository를 오가는 개발자와 운영자의 탐색 비용은 줄지만 권한·알림·우선순위를 바꾸는 기능은 아니므로 업무 triage 규칙을 대신하지는 않습니다.
- **발표일:** 2026-11-20 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-20-pin-your-favorite-repositories-to-your-dashboard)

## 보안·클라우드·플랫폼

### GitHub security advisory 세부 권한 일반 제공

조직 소유자가 custom repository role에 advisory 조회, 생성·편집·관리, private vulnerability report 수락, advisory 공개·CVE 요청 권한을 각각 부여할 수 있게 됐습니다. repository administrator나 조직 전체 security manager 권한 없이 필요한 repository에만 접근을 제한할 수 있습니다.

- **중요한 이유:** 취약점 대응의 최소권한 분리가 가능해지지만 temporary private fork merge에는 여전히 관리자 권한이 필요하고 confidential comment 조건도 따로 확인해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-20-security-advisory-permissions-are-now-generally-available)

### GitHub Enterprise Server 3.23 release candidate

GHES 3.23 RC에는 air-gapped 환경에서도 CPU로 실행되는 AI secret detection preview, OpenSSF malicious-package advisory의 다중 생태계 확대, Dependabot version update의 기본 3일 cooldown이 포함됐습니다. OAuth 8시간 access token·refresh token preview와 dedicated Redis node 운영도 추가됐습니다.

- **중요한 이유:** 공급망 공격 대응과 격리망 탐지가 강화되지만 RC는 production용이 아니며 OAuth token 만료를 강제하기 전에 모든 client의 refresh-token 처리를 검증해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-20-github-enterprise-server-3-23-release-candidate)

### CloudWatch, EKS 오픈소스 도구 내장 관측성 제공

CloudWatch EKS Container Insights 8.0.0 이상이 Karpenter, KEDA, vLLM, KServe, SGLang, Ray와 Knative Serving dashboard를 제공합니다. OTel Container Insights를 켜면 model server의 queue·첫 token 시간·KV cache와 autoscaler loop를 pod·workload·node 문맥으로 볼 수 있습니다.

- **중요한 이유:** 별도 Prometheus·Grafana 운영 부담을 줄일 수 있지만 $0.08/GB ingestion 비용, metric cardinality와 민감한 model label 노출을 통제해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/cloudwatch-eks-kubernetes-tools/)

### ECS Action Logs, task·cluster·capacity provider까지 확대

ECS Action Logs가 image pull, EBS 권한, subnet IP 부족, container exit code와 health-check 중단 사유를 기록하고 instance 등록·draining과 managed scaling도 다룹니다. CloudWatch Logs, S3 또는 Data Firehose로 보낼 수 있습니다.

- **중요한 이유:** 배포·확장 실패의 원인 파악이 빨라지지만 cluster별 opt-in과 저장 대상 비용, ARN·상태 사유의 보존·접근 정책을 함께 설계해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-ecs-action-logs-expanded-troubleshooting)

## 데이터·이벤트 아키텍처

### DynamoDB vector search, range·IN·OR·NOT filter 지원

DynamoDB SearchVectors의 inline filter가 숫자 비교와 BETWEEN, IN, attribute_exists, AND·OR·NOT을 지원합니다. 가격·평점·게시일이나 brand 목록처럼 operational attribute를 vector 유사도 검색과 함께 서버에서 제한할 수 있습니다.

- **중요한 이유:** 상품 검색과 RAG의 사후 filtering 낭비를 줄이지만 filter selectivity, index 비용과 권한 경계가 embedding 검색 결과에 미치는 영향을 benchmark해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/dynamodb-vector-filters/)

### EventBridge custom bus, 관리형 webhook ingress 지원

EventBridge enhanced Custom event bus가 HTTPS endpoint를 만들고 HMAC signature, static token 또는 basic authentication으로 webhook을 검증한 뒤 event를 bus에 넣습니다. 별도 API endpoint와 compute 없이 SaaS·agent·물류 partner event를 subscriber로 route할 수 있습니다.

- **중요한 이유:** 주문·배송 webhook 수신 계층이 단순해지지만 signature secret rotation, replay 방지, schema validation, 중복 event와 subscriber idempotency는 여전히 application 책임입니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-eventbridge-webhook-events)

### Amazon MSK, Apache Kafka 4.2 지원

MSK Standard broker가 Kafka 4.2를 지원하며 production-ready Queues for Kafka, Eligible Leader Replicas 개선, 새 consumer rebalance protocol과 Streams Rebalance Protocol을 제공합니다. 기존 provisioned cluster도 rolling update로 올릴 수 있습니다.

- **중요한 이유:** point-to-point 병렬 처리와 rebalance가 개선되지만 client·connector 호환성, partition ordering과 consumer semantics를 staging에서 확인한 뒤 단계적으로 upgrade해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-msk-standard-version-42/)

### MSK Standard에서 Express broker로 in-place upgrade

Kafka 3.9 KRaft의 MSK Provisioned cluster를 endpoint와 consumer offset을 유지한 채 Standard에서 Express broker로 이동할 수 있게 됐습니다. topic을 자동 또는 batch로 옮기고 Standard broker를 남긴 채 검증·rollback한 뒤 decommission할 수 있습니다.

- **중요한 이유:** 별도 cluster cutover를 줄이지만 AWS의 최대 성능 수치는 workload별로 재검증해야 하며 topic migration 중 latency·capacity와 rollback 조건을 명확히 해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-msk-standard-brokers-to-express-brokers-in-place-upgrade)

### Aurora MySQL 8.4.12 일반 제공

Aurora MySQL-Compatible 8.4가 MySQL 8.4.12의 security enhancement와 bug fix를 반영했습니다. automatic minor upgrade와 AWS Organizations Upgrade Rollout Policy를 이용해 낮은 우선순위 환경부터 단계적으로 적용할 수 있습니다.

- **중요한 이유:** 이전 MySQL CVE 수정 수용이 권고되지만 query plan, driver, replication과 주문 transaction 회귀를 snapshot·staging에서 확인한 뒤 maintenance window를 잡아야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-aurora-mysql-8412-available/)

## 언어·프레임워크

### Lambda, Node.js 26 LTS runtime 지원

Lambda Web Functions와 Event Functions가 Node.js 26 managed runtime을 지원하고 Event Functions에는 base container image도 제공합니다. Temporal API와 Fetch API 개선을 사용할 수 있으며 Node.js 26의 security·bug fix 지원은 2029년 4월까지 예정돼 있습니다.

- **중요한 이유:** timezone 처리와 최신 web API를 runtime shim 없이 쓸 수 있지만 native dependency, ESM·test runner와 cold start를 기존 runtime과 비교해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-nodejs-26/)

### Lambda, Python 3.15 및 Web Functions preview 지원

Lambda Event Functions에서 Python 3.15가 일반 제공되고 Web Functions에서는 첫 Python runtime으로 public preview가 시작됐습니다. explicit lazy imports, frozendict·sentinel과 개선된 JIT를 사용할 수 있습니다.

- **중요한 이유:** web API와 startup 최적화 선택지가 늘지만 Web Functions는 preview이며 C extension wheel, lazy import 부작용과 JIT의 workload별 이득을 검증해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-python-315/)

### AWS Transform for .NET 11 일반 제공

AWS Transform가 .NET Framework 3.5 이상과 .NET 5~10의 C#·VB.NET 프로젝트를 .NET 11로 modernize하도록 지원합니다. desktop·mobile을 제외한 변환 결과는 Linux에서 실행할 수 있고 VB.NET, WinForms·WPF·Xamarin 등 preview 범위도 GA가 됐습니다.

- **중요한 이유:** legacy Windows workload 전환을 가속할 수 있지만 공급자의 최대 40% 비용 절감 주장은 workload별 검증이 필요하며 WCF·UI·native dependency의 동작은 수동 review가 필수입니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-transform-windows-dotnet-11/)

### AWS Transform, ASP.NET UI component porting 지원

AWS Transform가 legacy ASP.NET site의 third-party UI dependency를 찾아 Microsoft-native·오픈소스 control로 바꾸거나 vendor library 전환 지침을 남깁니다. 대상 UI framework용 code를 생성하되 vendor 유지 경로의 licensing과 마무리는 사용자가 처리합니다.

- **중요한 이유:** Web Forms 등 UI migration의 반복 작업을 줄일 수 있지만 accessibility, visual parity, event lifecycle과 license 준수는 generated code만으로 보장되지 않습니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-transform-ui-windows/)

- **중요한 이유:** 주문 마감·정산·재고 동기화의 scheduler 구성이 단순해지지만 at-least-once 실행을 전제로 transaction ID, 재시도 한도와 dead-letter 처리를 둬야 합니다.
