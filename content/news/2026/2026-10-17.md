# 2026-10-17 AI·IT 개발 뉴스

실행 시점 기준 최근 24시간의 발표를 우선하고 중요한 보안·개발 이슈는 최근 72시간까지 확장해 9개를 선정했습니다. Hacker News 등 커뮤니티와 프로젝트·기업 피드를 발견 경로로 살핀 뒤 공식 발표, 기술 원문과 NVD 기록으로 확인했습니다. 성능·규모 수치는 별도 독립 검증이 없는 경우 발표 주체의 측정입니다.

## AI

### Claude, NIST ECDSA 곡선 seed의 생성 기원을 재현

Anthropic은 Claude가 NIST P-192·P-224·P-256·P-384·P-521 등의 공개 seed가 1990년대 C 라이브러리의 `lrand48`을 Unix timestamp로 초기화해 생성됐음을 찾아냈다고 밝혔습니다. 공개 값과 160-bit 단위로 일치하도록 재현했고 일부 base point의 생성법도 설명했지만, B-163 seed와 일부 base point 선정 과정은 아직 풀지 못했습니다. Anthropic은 이것이 ECDSA의 취약점이나 새로운 공격이 아니며 기존 곡선을 바꿀 필요도 없다고 명시했습니다.

- **실무상 중요성:** 결제 서명이나 TLS에서 해당 곡선을 쓰는 팀이 긴급 교체할 사안은 아닙니다. 다만 암호 표준의 parameter provenance를 재현 가능한 code·artifact와 함께 남기는 것이 장기 신뢰와 audit에 중요하다는 사례입니다.
- **발표일:** 2026-10-16
- **원문:** [Anthropic — Claude reveals ECDSA curve origins](https://www.anthropic.com/research/ecdsa-curve-origins)

### Claude Code 팀, agent 시대의 code review 운영 방식 공개

Anthropic은 Claude Code codebase의 약 90%를 Claude가 작성하는 상황에서 사전 검증, 독립 subagent review, PR별 AI·보안 review, 자동 check, 위험도별 사람 승인과 rollback을 층으로 쌓은 과정을 공개했습니다. 6월부터 9월까지 merge된 PR 수가 두 배 이상 늘어난 동안 revert 비율은 40% 넘게 줄었다는 내부 지표도 제시했습니다. 낮은 위험 변경만 자동 검사를 통과하면 사람 승인 없이 갈 수 있고, 민감 경로·고위험 변경은 한두 명의 승인을 유지합니다.

- **실무상 중요성:** AI review 도입의 목표를 단순 처리량이 아니라 human wait time, comment, revert와 incident rate로 함께 측정하는 운영 모델을 참고할 수 있습니다. 주문·결제 code에는 변경 크기보다 자금 이동, 인증, CI 설정 같은 영향 경로를 기준으로 사람 승인과 소유 책임을 유지해야 합니다.
- **발표일:** 2026-10-15
- **원문:** [Claude Developer Platform — How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/)

## 개발 생태계

### GitHub, enterprise 오픈소스 라이선스 compliance 정식 출시

GitHub Enterprise Cloud의 GitHub Code Security 사용 repository에서 중앙 license policy를 ruleset으로 적용해, 새 dependency가 정책을 위반하면 merge 전에 조치하도록 하는 기능이 GA됐습니다. 위반 package의 제거·교체, 정책 변경 또는 예외 승인을 지원하며 license manager role, audit log, 정책 관리·package 판정 REST API도 제공합니다. Agent가 허용되지 않은 package를 추천하거나 추가하기 전에 API로 확인할 수도 있습니다.

- **실무상 중요성:** 여러 서비스와 agent가 dependency를 빠르게 추가하는 조직은 license review를 사후 inventory가 아니라 PR gate로 옮길 수 있습니다. 자동 차단 전에는 transitive dependency, dual license, 사내 exception owner와 emergency override를 정리해 false positive가 배포를 멈추지 않게 해야 합니다.
- **발표일:** 2026-10-16
- **원문:** [GitHub Changelog — Open source license compliance generally available](https://github.blog/changelog/2026-10-16-open-source-license-compliance-generally-available/)

### GitHub Actions, Xcode 27 runner image 정식 제공

GitHub가 macOS 27과 Xcode 27 toolchain·Apple SDK를 포함한 hosted runner image를 GA했습니다. Workflow의 `runs-on`에 `xcode-27` 또는 `xcode-27-xlarge`를 지정하며 Apple Silicon arm64 runner에서만 제공되고 Intel runner에는 제공되지 않습니다. 기존 preview label 사용자는 workflow 수정 없이 GA image를 이용합니다.

- **실무상 중요성:** iOS commerce app은 Xcode·SDK 갱신 시 결제 SDK, signing, architecture별 native dependency와 snapshot test를 새 image에서 재검증해야 합니다. Image label만 고정해도 포함 도구는 갱신될 수 있으므로 installed-software manifest와 build artifact provenance를 함께 기록하는 편이 안전합니다.
- **발표일:** 2026-10-15
- **원문:** [GitHub Changelog — Xcode 27 runner image generally available](https://github.blog/changelog/2026-10-15-xcode-27-runner-image-generally-available/)

## 웹·클라우드·인프라

### RPKI-valid 인터넷 route 비율 1년 만에 54.0%에서 70.3%로 증가

IPinfo가 1년간의 daily routing data를 분석한 결과 RPKI-valid routed prefix 비율이 54.0%에서 70.3%로 올랐고, 중국의 IPv4 valid 비율 상승이 전체 증가의 큰 부분을 차지했습니다. Invalid route의 중앙값 관측 지점은 valid route 596곳에 비해 2곳으로, route origin validation이 실제 전파를 크게 제한하는 모습도 관측됐습니다. 그러나 covered IPv4 route의 16.2%는 느슨한 `maxLength` 때문에 위조된 more-specific route도 valid가 될 수 있다고 지적했습니다.

- **실무상 중요성:** 자체 ASN·IP prefix로 결제 API나 storefront를 운영한다면 ROA 생성만으로 끝내지 말고 실제 announce와 같은 prefix 길이로 최소화하고 expiration·coverage를 감시해야 합니다. Cloud provider·CDN 장애 대응에서도 BGP 상태와 RPKI validity를 application monitor와 별도로 확인할 필요가 있습니다.
- **발표일:** 2026-10-15
- **원문:** [IPinfo — RPKI Now Protects 70% of Internet Routes](https://ipinfo.io/blog/rpki-protects-70-internet-routes)

### 주요 browser 지원을 갖춘 JPEG XL, 웹에서는 AVIF와 workload별 비교 필요

Jake Archibald가 최신 encoder와 여러 image 유형을 같은 지각 품질에 맞춰 비교한 결과, lossy 사진·screenshot·투명 image에서는 대체로 AVIF가 더 작고 decode도 빨랐으며 lossless와 기존 JPEG의 무손실 재압축에서는 JPEG XL이 강점을 보였습니다. JPEG XL encoder 구현과 effort 설정에 따라 결과가 크게 달랐고, AVIF의 4:2:0을 무조건 기본값으로 쓰는 것도 권하지 않았습니다. 이는 특정 image set과 구현을 사용한 저자의 benchmark이지 모든 workload에 대한 보편적 결론은 아닙니다.

- **실무상 중요성:** 상품 image pipeline은 format 이름만으로 결정하지 말고 실제 catalog의 사진·문자·투명 배경을 대상으로 크기, encode 비용, decode 시간과 시각 품질을 측정해야 합니다. `picture` fallback, CDN cache key, browser support와 원본 보존을 포함해 점진적으로 전환하는 편이 안전합니다.
- **발표일:** 2026-10-15
- **원문:** [Jake Archibald — JPEG XL vs AVIF for web use-cases](https://jakearchibald.com/2026/jpeg-xl-vs-avif/)

## 보안

### OpenBSD, 37년 된 shared-memory counter overflow에서 이어지는 local root 경로 수정

Calif 연구진은 signed 16-bit shared-memory attachment counter를 반복 `fork`로 overflow시켜 use-after-free를 만들고, 별도 kernel out-of-bounds write와 결합해 root 권한을 얻는 exploit chain을 공개했습니다. 연구진은 KARL·SMAP·SMEP가 켜진 환경에서도 예측 가능한 allocator와 kernel pointer를 이용했다고 설명했으며 관련 문제는 OpenBSD errata 026과 018에서 수정됐습니다. 공격에는 local code execution과 여러 단계의 heap grooming·race가 필요합니다.

- **실무상 중요성:** OpenBSD host 운영자는 설명만 보고 개별 mitigation을 조합하기보다 사용 release의 errata와 syspatch 적용 여부를 확인하고, multi-user·untrusted workload host를 우선 patch해야 합니다. 오래된 integer type 하나가 별도 memory corruption과 결합돼 mitigation을 우회한 만큼 kernel·native code review에서는 counter 폭과 wraparound를 독립 위험으로 다뤄야 합니다.
- **발표일:** 2026-10-16
- **원문:** [Calif — Big Fish: Exploiting a 37-Year-Old Kernel Bug in OpenBSD](https://calif.io/research/big-fish)

### GitHub, PR용 AI Scan과 code-scanning Agentic Autofix 정식 출시

GitHub의 AI Scan은 CodeQL이 아직 충분히 다루지 않는 PHP, Shell, Terraform HCL, Dockerfile, JSP, Blazor 등의 PR 변경에서 취약점을 찾아 설명과 수정안을 제시합니다. 별도로 Agentic Autofix는 default branch의 code-scanning alert를 지정받아 관련 파일을 탐색하고 수정한 뒤 CodeQL 재실행으로 alert 해소를 검증해 draft PR을 엽니다. AI Scan 결과는 advisory라 merge를 직접 차단할 수 없고, Autofix는 정책 활성화와 사람의 review가 필요하며 AI credit·Actions minute를 사용합니다.

- **실무상 중요성:** 탐지 범위를 넓히되 AI Scan을 blocking security control로 오해하면 안 되며 기존 SAST·test·review를 유지해야 합니다. 자동 수정 PR은 결제 금액, 권한, webhook 검증 같은 business invariant test와 rollback 가능한 작은 변경 단위로 검토해야 합니다.
- **발표일:** 2026-10-15
- **원문:** [GitHub Changelog — AI Scan for pull requests generally available](https://github.blog/changelog/2026-10-15-ai-scan-for-pull-requests-generally-available/) · [Agentic autofix GA](https://github.blog/changelog/2026-10-15-agentic-autofix-for-code-scanning-alerts-general-availability/)

## 커머스·주문·결제

### WooCommerce 결제 plugin에서 결제 완료 위조·계정 탈취 취약점 다수 공개

NVD에는 Trust Payments Gateway 3.1.0 미만에서 provider 응답의 authenticity·order binding·amount를 확인하지 않아 인증 없는 공격자가 임의 주문을 결제 완료로 바꿀 수 있는 CVE-2026-87843이 게시됐습니다. Walletdoc Payment Gateway 1.8.5 미만도 기본값이 빈 webhook secret이고 SQL injection 문제가 있어 임의 주문 paid 처리 위험이 있는 CVE-2026-103307의 영향을 받습니다. Abandoned Cart Pro 10.8.0 이하의 CVE-2026-97657은 변조 가능한 recovery token과 우회 가능한 HMAC 검사 때문에 피해자 계정 takeover로 이어질 수 있습니다.

- **실무상 중요성:** 해당 plugin과 version을 즉시 inventory하고 고정 version으로 올리거나 비활성화한 뒤, 최근 주문 상태 변경·webhook·관리자 login을 조사해야 합니다. 결제 완료는 browser return parameter가 아니라 provider가 서명한 server-to-server event의 signature, merchant·order ID, amount, currency와 replay 방지를 모두 검증한 뒤 idempotent하게 반영해야 합니다.
- **발표일:** 2026-10-14 (NVD 게시)
- **원문:** [NVD — CVE-2026-87843](https://nvd.nist.gov/vuln/detail/CVE-2026-87843) · [CVE-2026-103307](https://nvd.nist.gov/vuln/detail/CVE-2026-103307) · [CVE-2026-97657](https://nvd.nist.gov/vuln/detail/CVE-2026-97657)

## 개발자 체크포인트

- **결제 plugin과 webhook을 먼저 점검하세요.** 영향 version을 차단·upgrade하고 주문 paid 전환 log를 재검토하며 signature, amount·currency·order binding과 replay 방지를 통합 test로 고정하세요.
- **AI 생성 code의 위험도를 business impact로 분류하세요.** 자금 이동, 인증, secret, CI workflow와 database migration은 자동 review가 통과해도 사람 승인과 명시적 rollback을 요구하세요.
- **Dependency 정책을 PR 단계로 당기세요.** License allowlist·exception owner를 정하고 agent가 package를 추가하기 전에 API 또는 lockfile check로 검증하세요.
- **Edge 신뢰성을 application 밖에서도 검증하세요.** 자체 prefix의 ROA와 `maxLength`를 점검하고 RPKI·BGP 이상을 CDN·API health와 함께 alerting하세요.
- **상품 image는 실제 catalog로 benchmark하세요.** AVIF와 JPEG XL을 품질, bytes, encode 비용, decode 시간으로 비교하고 fallback·cache key·원본 보존을 확인하세요.
