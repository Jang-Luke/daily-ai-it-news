### Bedrock AgentCore Identity, OAuth 2.0 discovery URL 지원

AWS는 AgentCore Identity의 inbound JWT authorization과 outbound OAuth credential provider에서 OIDC뿐 아니라 OAuth 2.0 authorization server discovery URL을 지원한다고 발표했습니다. 표준 discovery metadata를 쓰는 non-OIDC server를 연결할 수 있지만 issuer, audience, scope와 key rotation 검증은 배포 전 시험해야 합니다.

- **중요한 이유:** agent가 외부 API credential을 획득하는 범위가 넓어져 인증 server 통합은 쉬워지지만 trust boundary도 함께 커집니다.
- **발표일:** 2026-11-13 KST
- **원문:** [AWS — Bedrock AgentCore OAuth 2.0 discovery](https://aws.amazon.com/about-aws/whats-new/2026/11/bedrock-agentcore-oauth2-discovery/)

## 보안·플랫폼

### GitHub AI Scan, REST API로 조직·repository 설정 관리

GitHub code scanning의 AI Scan을 조직과 repository 수준에서 REST API로 켜고 끌 수 있는 public preview가 공개됐습니다. 중앙 policy automation에 연결할 수 있지만 preview API의 schema·권한 변경 가능성과 AI 분석 결과의 false positive를 고려해야 합니다.

- **중요한 이유:** 다수 repository의 보안 설정 drift를 줄일 수 있으나 기존 CodeQL·branch protection과 중복 또는 공백이 없는지 확인해야 합니다.

- **원문:** [GitHub Changelog — Manage AI Scan using the REST API](https://github.blog/changelog/2026-11-13-manage-ai-scan-for-repositories-using-the-rest-api)

### AWS Security Hub CSPM, Organizations 선언형 정책 지원

Security Hub CSPM이 AWS Organizations declarative policy로 account·region별 표준과 control을 중앙 관리하도록 확장됐습니다. 신규 account에도 baseline을 자동 적용하고 drift를 줄일 수 있지만 기존 central configuration과의 우선순위, 예외 account와 region별 요구를 migration 전에 정리해야 합니다.

- **중요한 이유:** 조직 보안 baseline을 코드처럼 일관되게 적용할 수 있어 multi-account 운영의 누락 위험을 낮춥니다.
- **발표일:** 2026-11-13 KST
- **원문:** [AWS — Security Hub CSPM declarative policies](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-cspm-org-policies/)

### AWS Secrets Manager, account 간 secret 복제 지원

Secrets Manager가 primary secret을 다른 AWS account로 동기화하는 cross-account replication을 지원합니다. replica는 대상 account의 customer-managed KMS key로 암호화된 독립 resource이며 rotation도 전파되지만, 승격·장애조치 때 application이 어느 secret을 읽는지 runbook으로 검증해야 합니다.

- **중요한 이유:** 복구 account에 최신 secret을 격리해 둘 수 있지만 잘못된 복제 권한은 credential의 blast radius를 넓힐 수 있습니다.
- **발표일:** 2026-11-13 KST
- **원문:** [AWS — Secrets Manager cross-account replication](https://aws.amazon.com/about-aws/whats-new/2026/11/secrets-manager-cross-account/)

### AWS Batch on EKS, capabilities·seccomp·pod 보안 설정 추가

AWS Batch의 EKS job definition에서 Linux capabilities, seccomp profile, `fsGroup` 같은 pod-level security context를 설정할 수 있게 됐습니다. Kubernetes Pod Security Standards restricted profile 아래에서 필요한 privilege와 syscall만 허용할 수 있으며 container 설정이 pod 기본값보다 우선합니다.

- **중요한 이유:** batch workload의 최소 권한 적용이 쉬워지지만 image와 job별 실제 syscall을 측정해 과도한 capability를 제거해야 합니다.
- **발표일:** 2026-11-13 KST
- **원문:** [AWS — Batch on EKS security context](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-batch-eks-security-context/)

## 데이터베이스·클라우드·아키텍처

### Aurora PostgreSQL express configuration, CloudFormation 지원

Aurora PostgreSQL의 express configuration을 CloudFormation에서 선언할 수 있게 됐습니다. `AWS::RDS::DBCluster`의 create-only property 하나로 cluster와 primary instance를 함께 만들 수 있어 template은 단순해지지만 변경·교체 동작과 production parameter, backup 설정을 명시적으로 확인해야 합니다.

- **중요한 이유:** 빠른 IaC 배포에 유리하되 간소화된 기본값이 운영 database의 가용성·보존 정책을 대신하지는 않습니다.
- **발표일:** 2026-11-14 KST
- **원문:** [AWS — Aurora PostgreSQL express configuration in CloudFormation](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-postgresql-cloudformation/)

### RDS for Oracle, minor upgrade·정기 maintenance 중단 시간 단축

RDS for Oracle은 maintenance 시작 전에 필요한 resource를 최대 30분 앞서 준비해 automatic minor version upgrade와 예약된 OS update의 offline 시간을 줄입니다. AWS가 중단 단축을 제공하더라도 application connection retry, transaction recovery와 maintenance window 관측은 그대로 유지해야 합니다.

- **중요한 이유:** 주문·결제 database의 patch 적용 부담을 낮출 수 있지만 실제 중단 상한과 failover 동작은 staging에서 확인해야 합니다.
- **발표일:** 2026-11-13 KST
- **원문:** [AWS — RDS for Oracle reduced maintenance downtime](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-oracle-reduces-maintenance-downtime-for-amvu-scheduled-upgrades/)

### AWS Systems Manager, Google Cloud VM 자동 onboarding

Systems Manager Cloud Connector가 Google Cloud VM에 SSM Agent를 대규모로 자동 배포하고 AWS·on-premises·Azure 자원과 함께 관리하도록 확장됐습니다. Session Manager, patch, inventory와 automation을 통합할 수 있지만 GCP service account 권한, egress와 control-plane 장애 의존성을 따져야 합니다.

- **중요한 이유:** multi-cloud 운영 절차를 표준화할 수 있으나 한 관리 plane의 장애나 credential 침해가 여러 cloud로 번지지 않도록 분리해야 합니다.
- **발표일:** 2026-11-13 KST
- **원문:** [AWS — Systems Manager Google Cloud support](https://aws.amazon.com/about-aws/whats-new/2026/11/systems-manager-google-cloud-support/)

### Amazon Cognito, OAuth 2.0 token exchange 지원

Cognito가 RFC 8693 token exchange를 지원해 service나 AI agent가 사용자 token을 특정 downstream audience와 좁은 scope의 새 token으로 교환할 수 있게 됐습니다. actor token을 쓰면 `act` claim으로 중개자를 식별할 수 있고 refresh token은 발급되지 않습니다.

- **중요한 이유:** MCP server와 backend가 원래 사용자 token을 그대로 전달하는 관행을 줄일 수 있지만 audience·scope 검증과 delegated action 감사가 필수입니다.
- **발표일:** 2026-11-13 KST
- **원문:** [AWS — Cognito OAuth 2.0 token exchange](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-token-exchange/)
