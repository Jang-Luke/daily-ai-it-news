AWS는 자격을 갖춘 고객이 OpenAI의 전문 사이버보안 모델 Daybreak Red: GPT-5.6 Cyber를 GovCloud의 `bedrock-runtime` endpoint에서 이용할 수 있다고 발표했습니다. 취약점 연구·exploit 재현·완화 개발처럼 승인된 고난도 작업을 대상으로 하며, 일반 모델보다 낮은 거부 임계값 대신 신원 확인·모니터링·접근통제를 강화합니다.

- **중요한 이유:** 방어 연구를 agent workflow에 넣을 수 있지만 강력한 dual-use 역량입니다. 별도 계정·승인된 target allowlist·egress 제한·tool-call 감사와 산출물 검토가 선행돼야 합니다.
- **발표일:** 2026-11-25 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/gpt-daybreak-red-runtime-govcloud/)

### Claude Ship, PR 검토 이후 수정·정책 승인까지 연결

Anthropic의 beta 기능 Claude Ship은 GA인 Code Review에 PR Steward와 Claude Approvals를 연결합니다. Steward는 CI 실패·merge conflict·review feedback을 수정하되 merge하지 않고, Approvals는 repository 안의 자연어 정책에 따라 자동 승인 또는 사람 검토를 요구합니다.

- **중요한 이유:** coding agent의 후속 업무를 줄이지만 작성·검토·승인이 같은 자동화 경로에 집중될 수 있습니다. observe-only 도입, branch protection, 민감 경로 CODEOWNER와 인간 승인을 유지해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [Anthropic](https://claude.com/resources/articles/introducing-claude-ship)

## 보안·플랫폼

### OpenAI·Cisco, 재시작 없이 Linux 취약 경로를 막는 Shirudo 공개

Shirudo는 eBPF shield를 실행 중인 Linux process에 적용해 patch·재시작 전 취약 code path를 임시 차단하는 open-source runtime입니다. operator 승인, shield 서명, eBPF verifier와 TPM 기반 변경 증거를 결합하며 양사는 Java4Shell 통제 시험을 제시했습니다.

- **중요한 이유:** 긴급 patch의 노출 시간을 줄이는 보완책이지 patch 대체재는 아닙니다. false positive, kernel·architecture 호환성, 서명 key와 rollback 절차를 검증해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [OpenAI](https://openai.com/index/introducing-shirudo)

### AWS Sign-In, OAuth 로그인 지속시간을 최대 90일로 설정

관리자는 IAM user·role별 OAuth Sign-In session을 최대 90일까지 설정할 수 있습니다. AWS CLI의 `aws login`, AWS MCP Server와 OAuth application에 적용되며 console session에는 영향을 주지 않고, 명시적으로 설정하지 않으면 기존 한도가 유지됩니다.

- **중요한 이유:** 장기 agent workflow에서 static access key를 줄일 수 있지만 90일 renewable credential도 탈취 시 영향이 큽니다. 민감 role은 짧게 유지하고 device posture·revoke 절차·CloudTrail 탐지를 결합해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/configurable-aws-sign-in-duration/)

### AWS WAF, LLM·MCP·A2A endpoint 자동 발견과 Guardrails 검사 GA

API Gateway API Portal이 traffic log와 service configuration에서 AI endpoint와 public shadow MCP server를 찾고, WAF AI Security managed rule이 malformed MCP·A2A message를 차단합니다. 선택적 content inspection은 Bedrock Guardrails로 prompt injection·jailbreak와 response 민감정보를 검사합니다.

- **중요한 이유:** agent endpoint inventory를 중앙화할 수 있지만 암호화 payload·streaming·custom transport의 blind spot과 별도 비용이 남습니다. 개인정보 전달 범위와 false positive를 canary로 검증해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/)

### RDS for SQL Server, instance당 database 한도 100개에서 500개로 확대

4 vCPU 이상 non-burstable instance의 지원 edition·배포 형태에서 최대 500개 database를 운영할 수 있습니다. 다수 tenant database를 여러 instance에 분산하던 SaaS가 consolidation해 patch·monitoring·license 비용을 줄일 선택지가 생겼습니다.

- **중요한 이유:** database 수 한도 확대가 CPU·I/O·tempdb·backup window와 장애 blast radius를 없애지는 않습니다. noisy neighbor, restore 시간과 tenant별 connection pool을 부하시험해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-sqlserver-supports-500-databases-per-instance)

### OpenSearch 3.9, vector 압축과 agent gRPC streaming 추가

Amazon OpenSearch Service가 3.9를 지원합니다. half-float·bf16, 2-bit·4-bit scalar quantization과 Base64 vector ingestion으로 vector memory·payload를 줄이고, model prediction과 agent execution에 token 단위 gRPC streaming을 추가했습니다.

- **중요한 이유:** 검색 비용과 응답 체감을 개선할 수 있지만 압축률과 recall의 교환관계가 있습니다. 실제 상품 catalog·검색 query로 recall@k, latency, index size와 재색인 시간을 비교해야 합니다.
- **발표일:** 2026-11-24 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-opensearch-3-9)

### OpenSearch Serverless 차세대 구조, Cape Town region으로 확대

AWS가 compute와 storage를 분리하고 idle 시 scale-to-zero하는 차세대 OpenSearch Serverless를 Africa (Cape Town)에 제공하기 시작했습니다. 검색·vector·observability workload가 대상이며 AWS는 peak provision 대비 최대 60% 절감을 주장합니다.

- **중요한 이유:** 지역 내 데이터 residency가 필요한 agent 검색에 선택지가 늘지만 비용 절감률은 traffic pattern에 따라 다릅니다. cold start, minimum billing, ingest spike와 cross-region DR을 실측해야 합니다.
- **발표일:** 2026-11-25 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-serverless-available-cape-town-region/)

AWS는 RDS Database Preview Environment에서 PostgreSQL 19.0을 시험할 수 있게 했습니다. preview 환경은 production SLA·장기 보존을 위한 것이 아니라 application·extension 호환성을 미리 점검하는 용도입니다.
