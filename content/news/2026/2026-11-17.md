# 2026-11-17 AI·IT 개발 뉴스

최근 24시간의 공식 발표·릴리스를 우선했습니다. 공급자 설명과 사전판 변경은 독립적으로 검증된 성능이나 안정판과 구분했습니다.

## AI Agent·개발 도구

### GitHub Copilot 주간 릴리스, GHES 연결·세션 주의 표시·신규 모델 묶음 공개

GitHub가 11월 9일 주간 Copilot 변경을 한 번에 정리했습니다. Copilot app의 GitHub Enterprise Server 저장소 연결, VS Code의 주의가 필요한 agent session 표시, Claude와 Gemini 계열 신규 모델 시험이 핵심이며, 각 기능의 조직별 제공 범위는 문서에서 확인해야 합니다.

- **중요한 이유:** agent가 사내 저장소와 장시간 작업할수록 권한·데이터 경계와 사람의 개입 시점을 함께 관리해야 합니다.
- **발표일:** 2026-11-17 KST
- **원문:** [GitHub Changelog — Copilot weekly releases](https://github.blog/changelog/2026-11-16-github-copilot-weekly-releases-november-9)

### GitHub Copilot, 11월 16일 일부 모델 지원 종료

GitHub는 공지했던 일부 Copilot 모델을 Chat, inline edit, ask·agent mode와 code completion 대부분에서 실제로 중단했습니다. 모델 이름을 workflow나 조직 정책에 고정한 팀은 fallback 동작, 승인 모델 목록과 평가 기준을 즉시 점검해야 합니다.

- **중요한 이유:** 모델 종료는 자동화 품질뿐 아니라 규정 준수, 비용과 재현 가능한 agent 실행을 동시에 바꿉니다.
- **발표일:** 2026-11-17 KST
- **원문:** [GitHub Changelog — models deprecated](https://github.blog/changelog/2026-11-16-github-copilot-models-deprecated-on-november-16-2026)

### Amazon WorkSpaces, 업무용 AI agent 연결·통제 기능 발표

AWS는 agent가 ERP 거래나 업무용 앱을 다루도록 WorkSpaces 환경에서 설정·연결·governance를 단순화하는 기능을 발표했습니다. 공급자 설명 단계이므로 실제 권한 위임, 화면·입력정보 노출, 세션 격리와 감사로그 범위를 pilot에서 검증해야 합니다.

- **중요한 이유:** 사람용 desktop을 agent 실행 경계로 쓰면 기존 IAM만으로 설명되지 않는 UI 조작과 credential 노출 위험이 생깁니다.
- **발표일:** 2026-11-17 KST
- **원문:** [AWS — AI agents with Amazon WorkSpaces](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-workspaces-AI-agents-connect-govern)

### AWS DevOps Agent, GovCloud US-West 제공

AWS DevOps Agent가 AWS GovCloud US-West에서 제공되기 시작했습니다. 규제 환경에서도 incident 분석·예방과 reliability 작업을 agent에 맡길 선택지가 늘었지만, 자동 변경의 승인 경계와 증거 보존은 별도로 설계해야 합니다.

- **중요한 이유:** 운영 agent 도입은 탐지 속도를 높일 수 있으나 잘못된 remediation의 영향 반경을 제한하는 change gate가 필수입니다.
- **발표일:** 2026-11-17 KST
- **원문:** [AWS — DevOps Agent in GovCloud](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-devops-agent-govcloud-west/)

## 보안·플랫폼

### GitHub AI Scan, 여러 저장소를 일괄 시작

GitHub는 CodeQL이 지원하지 않는 언어와 추가 취약점 유형을 AI로 찾는 AI Scan을 여러 repository에 한 번에 시작할 수 있게 했습니다. 결과는 보안 사실의 확정 판정이 아니라 triage 입력으로 다루고, false positive와 민감 코드 처리 정책을 확인해야 합니다.

- **중요한 이유:** 조직 전체 rollout은 coverage를 빠르게 넓히지만 중앙 실행이 개발팀의 검토 용량을 초과하지 않도록 단계화해야 합니다.
- **발표일:** 2026-11-17 KST
- **원문:** [GitHub Changelog — Bulk start AI Scan](https://github.blog/changelog/2026-11-16-bulk-start-ai-scan-for-repositories)

### AWS KMS, Resource Access Manager로 계정 간 key 공유

AWS KMS가 AWS RAM과 통합돼 여러 계정에 KMS key를 공유하는 절차를 일관되게 관리할 수 있게 됐습니다. 공유 편의성과 별개로 key policy, grant, 조직 경계와 삭제·회수 절차가 합쳐져 과도한 복호화 권한을 만들지 않는지 검토해야 합니다.

- **중요한 이유:** 결제·주문 데이터의 암호화 key 공유는 운영을 단순화하지만 권한 오류의 blast radius도 키울 수 있습니다.
- **발표일:** 2026-11-17 KST
- **원문:** [AWS — KMS key sharing with RAM](https://aws.amazon.com/about-aws/whats-new/2026/11/kms-key-sharing-resource-access-manager/)

### Secrets Manager, Auth0·Okta·Palo Alto 외부 secret 관리 지원

AWS Secrets Manager가 Auth0, Okta와 Palo Alto Networks의 external secret을 관리하고 rotation하는 기능을 추가했습니다. 장기 credential을 줄일 수 있지만 대상 서비스별 rotation 실패, 이전 값의 유효기간과 비상 복구 절차를 확인해야 합니다.

- **중요한 이유:** SaaS·보안제품 credential도 cloud secret lifecycle에 편입해 수동 갱신 누락을 줄일 수 있습니다.
- **발표일:** 2026-11-16 KST
- **원문:** [AWS — managed external secrets](https://aws.amazon.com/about-aws/whats-new/2026/11/secrets-manager-managed-external-secrets-auth0-okta-palo-alto/)

### IAM Identity Center, VPC endpoint·network access control 지원

AWS IAM Identity Center가 PrivateLink 기반 interface VPC endpoint와 network access control을 지원합니다. identity traffic을 public Internet에서 분리할 수 있지만 DNS, endpoint policy와 비상 접근 경로를 함께 시험해야 합니다.

- **중요한 이유:** 관리 plane 접근을 private path로 제한해 identity 서비스의 노출면과 egress 의존성을 줄일 수 있습니다.
- **발표일:** 2026-11-16 KST
- **원문:** [AWS — IAM Identity Center VPC endpoints](https://aws.amazon.com/about-aws/whats-new/2026/11/iam-identity-center-vpc-endpoints/)

## 데이터베이스·클라우드·아키텍처

### Amazon S3 Vectors, vector·full-text hybrid search 지원

S3 Vectors가 하나의 query에서 vector similarity와 full-text search를 결합합니다. 의미 유사성과 정확한 상품명·코드 일치를 함께 반영할 수 있지만 ranking 품질, filter semantics와 latency를 실제 corpus로 측정해야 합니다.

- **중요한 이유:** RAG와 상품검색에서 별도 keyword engine을 조합하는 복잡성을 줄일 가능성이 있습니다.
- **발표일:** 2026-11-17 KST
- **원문:** [AWS — S3 Vectors hybrid search](https://aws.amazon.com/about-aws/whats-new/2026/11/s3-vectors-hybrid-search/)

### Amazon Redshift, Iceberg multi-statement transaction·충돌 해결·time travel 추가

Redshift가 Apache Iceberg table에 여러 statement를 묶는 transaction, 자동 write-conflict resolution과 time travel을 지원합니다. 동시 writer가 있는 data pipeline은 isolation 보장, snapshot 보존비용과 rollback 시간을 기존 방식과 비교해야 합니다.

- **중요한 이유:** lakehouse의 복합 갱신과 과거 상태 조회를 warehouse query 안에서 다루기 쉬워집니다.
- **발표일:** 2026-11-17 KST
- **원문:** [AWS — Redshift and Iceberg transactions](https://aws.amazon.com/about-aws/whats-new/2026/11/redshift-time-travel-multi-statement/)

### AWS Backup, RDS용 logically air-gapped vault 지원

AWS Backup의 logically air-gapped vault가 RDS DB instance를 지원합니다. ransomware·관리계정 침해에 대비한 격리 복사본을 만들 수 있지만 cross-account restore 권한, RPO·RTO와 실제 복구 rehearsal가 필요합니다.

- **중요한 이유:** 주문·결제 database의 backup이 존재한다는 사실보다 독립된 계정에서 정해진 시간 안에 복구되는지가 중요합니다.
- **발표일:** 2026-11-16 KST
- **원문:** [AWS — air-gapped vault for RDS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-backup-air-gapped-vault-rds/)

### Amazon VPC, shared networking 비용 배분 기능 도입

AWS가 shared VPC·networking 비용을 실제 사용을 유발한 resource에 나눠 부과하는 Networking Flexible Cost Allocation을 발표했습니다. chargeback을 정교화할 수 있지만 allocation 규칙이 egress 최적화나 서비스 수익성 판단을 왜곡하지 않는지 확인해야 합니다.

- **중요한 이유:** 공용 NAT·network 경로 비용을 주문·검색·결제 서비스별로 추적해 FinOps 책임을 명확히 할 수 있습니다.
- **발표일:** 2026-11-16 KST
- **원문:** [AWS — Networking Flexible Cost Allocation](https://aws.amazon.com/about-aws/whats-new/2026/11/networking-flexible-cost-allocation/)

### GitHub Enterprise Cloud, account당 budget 한도 4만 개로 확대

GitHub는 Enterprise Cloud account에서 만들 수 있는 budget을 1만 개에서 4만 개로 늘렸습니다. 사용자·cost center별 세분화가 쉬워졌지만 budget alert와 실제 차단 동작을 혼동하지 말고 자동화 계정의 예외를 점검해야 합니다.

- **중요한 이유:** 대규모 조직이 Copilot·Actions 등 사용비를 팀과 서비스 단위로 더 촘촘하게 통제할 수 있습니다.
- **발표일:** 2026-11-17 KST
- **원문:** [GitHub Changelog — 40,000 budgets](https://github.blog/changelog/2026-11-16-budget-limit-increased-to-40000-budgets-per-account)

## 언어·프레임워크·웹 런타임

### workerd v1.20261116.1, module fallback·timer·Rust build 개선

workerd 최신 릴리스는 legacy module registry의 fallback redirect를 제한하고, 이미 만료된 KJ timer 처리와 Rust remote build 정리를 포함합니다. Workers runtime에 밀접한 변경이므로 custom module fallback이나 Rust binding을 쓰는 프로젝트는 회귀 test를 실행해야 합니다.

- **중요한 이유:** module resolution 경계와 event-loop timer 변경은 드물게 routing·scheduling 동작 차이를 만들 수 있습니다.
- **발표일:** 2026-11-16 KST
- **원문:** [cloudflare/workerd v1.20261116.1](https://github.com/cloudflare/workerd/releases/tag/v1.20261116.1)

### Next.js 16.5 canary.52, stale type 정리·Turbopack persistence 변경

Next.js 16.5.0-canary.52는 `next typegen`과 build에서 오래된 `.next/dev/types`를 제거하고 deployment ID code generation을 단순화했습니다. Turbopack collectible dependent 저장과 persistence block test도 바뀌었으며 canary이므로 production 안정판으로 간주하면 안 됩니다.

- **중요한 이유:** type artifact 잔존으로 생기는 잘못된 build 결과를 줄일 수 있지만 사전판의 cache·incremental build 회귀를 검증해야 합니다.

- **원문:** [vercel/next.js v16.5.0-canary.52](https://github.com/vercel/next.js/releases/tag/v16.5.0-canary.52)
