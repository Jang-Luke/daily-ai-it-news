### Google Cloud API Gateway, SSE·WebSocket·gRPC streaming public preview

Google Cloud API Gateway가 기존 API spec을 바꾸지 않고 SSE, chunked response, WebSocket, server·bidirectional gRPC streaming을 통과시키는 기능을 public preview로 열었습니다. 기존 API key·JWT·service account 인증, logging과 routing 정책을 유지하며 stream은 최대 1시간 열어 둘 수 있고, preview에서는 gateway 생성 시 `--enable-streaming`이 필요합니다.

- **실무상 중요성:** LLM token streaming과 실시간 API를 gateway 밖으로 우회하던 별도 경로를 줄일 수 있습니다. 장시간 연결의 quota·비용, client reconnect, backpressure와 중간 장애 시 idempotency를 load test로 확인하세요.
- **발표일:** 2026-10-22
- **원문:** [Google Developers Blog — Streaming comes to API Gateway](https://developers.googleblog.com/streaming-comes-to-api-gateway-real-time-and-ai-ready-apis-without-changing-your-spec/)

### Amazon OpenSearch Serverless, 기본 refresh interval 10초에서 5초로 단축

AWS는 OpenSearch Serverless의 search collection과 vector collection 기본 refresh interval을 10초에서 5초로 낮췄습니다. 새로 적재한 문서가 검색 결과에 보이는 기본 지연이 줄어들며, 별도 application 변경 없이 적용되는 service 동작 변경입니다.

- **실무상 중요성:** 상품 검색, 재고 탐색과 RAG index의 최신성이 개선되지만 database commit과 검색 노출 사이의 eventual consistency 자체가 사라지는 것은 아닙니다. 주문 확정·재고 차감처럼 강한 일관성이 필요한 판정은 여전히 원장 DB에서 수행해야 합니다.
- **발표일:** 2026-10-22
- **원문:** [AWS — OpenSearch Serverless 5-second default refresh interval](https://aws.amazon.com/about-aws/whats-new/2026/10/amazon-opensearch-serverless-supports-5-second-refresh-interval/)

Vite 8.3.5는 missing chunk import map, preload dependency hash, `server.origin` asset URL, HMR propagation과 resolver edge case 등을 수정했습니다. 기능 추가보다 build·bundled dev server의 안정화 release이므로 Vite 8 사용자는 lockfile 기반 재현 build와 SSR·HMR smoke test 후 patch update하는 것이 좋습니다.

- **발표일:** 2026-10-21
- **원문:** [Vite v8.3.5 release](https://github.com/vitejs/vite/releases/tag/v8.3.5)

### Deno 2.9.8

Deno 2.9.8은 dynamic import local file의 read permission 확인, N-API DataView bounds overflow, npm package link name 검증을 수정했습니다. 또한 손상된 eMudhra CA를 신뢰하지 않도록 TLS trust를 갱신하고 patched `rand` dependency를 반영했습니다. 권한 sandbox와 TLS에 의존하는 runtime 사용자는 behavior change를 확인하고 업데이트해야 합니다.

- **발표일:** 2026-10-21
- **원문:** [Deno v2.9.8 release](https://github.com/denoland/deno/releases/tag/v2.9.8)

## 개발자 체크포인트

- **결제·주문 webhook의 인증서를 inventory하세요.** eMudhra chain, certificate pinning, legacy client trust store를 찾아 대체 인증서 전환과 partner end-to-end test 일정을 잡으세요.
- **Agent와 CI의 장기 secret을 workload identity로 바꾸세요.** OIDC audience·issuer와 짧은 TTL을 제한하고, static key fallback 및 log 유출 경로를 제거하세요.
- **검색 freshness와 거래 일관성을 분리하세요.** OpenSearch의 5초 refresh는 상품 발견에는 유용하지만 가격·재고·주문 상태의 authoritative check는 transaction DB에서 다시 수행하세요.
- **Streaming API 장애 semantics를 명시하세요.** SSE·WebSocket·gRPC 재접속 시 중복 주문이나 중복 tool 실행이 생기지 않도록 resume token, idempotency key와 timeout을 contract test에 포함하세요.
- **AI 보안 자동화에는 사람의 승인 gate를 유지하세요.** 형식 증명, 취약점 patch와 ML experiment 결과를 독립 test·review 없이 production에 반영하지 마세요.
