# 2026-10-13 AI·IT 개발 뉴스

실행 시점 기준 최근 24시간의 발표와 사고를 우선해 10개를 선정했습니다. Hacker News, GitHub, Google News와 여러 기술·공식 피드를 발견 경로로 조사한 뒤 공식 발표, 저장소·패키지 레지스트리, 상태 페이지, 보안 연구 원문과 주요 보도로 확인했습니다. 일반 웹 검색 API와 Reddit은 실행 환경의 접근 제한으로 사용할 수 없었으며, 업체가 제시한 성능 수치는 독립 검증값이 아니라는 점을 구분했습니다.

- **실무상 중요성:** 주문 변경이나 환불처럼 개인정보와 실제 부작용이 있는 작업을 에이전트에 맡길 때는 기억 기능 자체가 새로운 데이터 보존·권한 경계가 됩니다. 모델 성능 주장과 별개로 결제 실행 전 승인, 최소 권한 도구, 개인정보 삭제 정책과 장기 작업의 중단·재개 일관성을 자체 시나리오로 검증해야 합니다.

## 웹·클라우드·인프라

### AWS, 일반 HTTP 서버를 그대로 실행하는 `Lambda Web Functions` 발표

AWS가 Express·Hono·Fastify·Next.js 같은 Node.js 서버가 포트를 열어 표준 HTTP 요청을 처리하도록 하는 Lambda Web Functions를 발표했습니다. 환경 하나가 최대 128개 요청을 동시에 처리하고 실제 CPU 사용 시간을 과금하며, 단일 명령의 다중 리전 배포·지연 기반 라우팅, revision 가중치 배포, CloudFront 비공개 origin과 VPC 연결을 지원합니다. 출시 시점에는 Node.js 24·Arm64이며 도쿄를 포함한 5개 리전에서 제공됩니다.

- **실무상 중요성:** I/O 대기가 많은 주문 조회·BFF를 이벤트 핸들러로 변환하지 않고 서버리스로 옮길 선택지가 생겼습니다. 기존 Lambda와 과금 단위·동시성 모델이 다르므로 DB connection pool, 세션 상태, cold start, revision 간 스키마 호환성과 리전별 데이터 규제를 부하 테스트로 비교해야 합니다.
- **발표일:** 2026-10-12
- **원문:** [AWS News Blog — Announcing AWS Lambda Web Functions](https://aws.amazon.com/blogs/aws/announcing-aws-lambda-web-functions-for-fast-consistent-web-app-performance-anywhere/)

### Microsoft, 추론 특화 `Azure Maia 300` 아키텍처 상세 공개

Microsoft가 장문맥·reasoning·decode 중심 추론을 겨냥한 3세대 Maia 300의 시스템 구조를 공개했습니다. 칩당 HBM4 288GB와 18TB/s 대역폭, 랙당 96개 가속기, 최대 12,288개 가속기의 superpod를 구성하며, Maia 200 대비 최대 7배의 랙 단위 토큰 처리량과 2.5배 이상의 와트당 성능을 주장합니다. 이 수치는 Microsoft의 세대 간 자체 비교이며 실제 워크로드 비용·지연 측정은 별도로 필요합니다.

- **실무상 중요성:** AI 비용 최적화가 GPU 한 장의 연산량보다 KV cache 위치, prefill/decode 분리와 랙·네트워크 배치 문제로 이동하고 있음을 보여줍니다. 대규모 상품 검색·상담 추론은 평균 토큰 가격뿐 아니라 긴 문맥의 tail latency, 장애 시 cross-rack 이동과 데이터 위치를 함께 측정해야 합니다.
- **발표일:** 2026-10-12
- **원문:** [Microsoft Azure Blog — Deep dive into Azure Maia 300 architecture](https://azure.microsoft.com/en-us/blog/deep-dive-into-azure-maia-300-architecture/)

### Cloudflare, Logpush 내보내기 전 SQL 변환 기능 정식 제공

Cloudflare가 Logpush 레코드를 목적지로 보내기 전에 SQL로 필터링·필드 재구성·민감정보 마스킹하는 Transformers를 정식 제공했습니다. Transformer는 데이터셋별 version으로 관리되고 dashboard와 API에서 미리보기·배포할 수 있으며 결과는 NDJSON으로 출력됩니다. Cloudflare는 Apache DataFusion·Arrow 기반 엔진을 전송 프로세스 안에 넣어 5,000행 합성 배치에서 약 3ms가 걸렸다고 자체 측정했습니다.

- **실무상 중요성:** 결제 로그가 SIEM·오브젝트 스토리지에 도달하기 전에 IP나 불필요한 필드를 줄여 비용과 노출 면적을 낮출 수 있습니다. 다만 마스킹 SQL의 누락도 곧 유출이므로 version review, 샘플뿐 아닌 property test, 원본 보존 정책과 장애 시 fail-open/fail-closed 동작을 확인해야 합니다.
- **발표일:** 2026-10-12
- **원문:** [Cloudflare Blog — Filter, reshape, and redact logs before export with Transformers](https://blog.cloudflare.com/transformers-on-logpush/)

## 보안

### Zod 4.6.6 패키지에 외부 payload를 가져오는 `preinstall` 코드 포함, 4.6.7 배포

Zod 저장소의 4.6.6 변경에는 `zod`와 `@zod/mini`에 `preinstall` 스크립트가 추가됐고, 이 코드는 Ethereum RPC에서 도메인 목록을 얻은 뒤 `/loader`의 payload를 내려받아 실행하도록 작성돼 있었습니다. npm 레지스트리 기록상 4.6.6은 10월 11일 게시됐고 10월 12일 4.6.7로 교체됐으며, 4.6.7 패키지에는 해당 install script가 없습니다. 공식 저장소에 별도 사고 보고가 확인되지 않은 상태이므로 침해 범위나 payload의 최종 행위는 단정할 수 없지만, 4.6.6 설치 흔적은 즉시 조사할 사안입니다.

- **실무상 중요성:** 널리 쓰이는 validation 의존성도 install 단계에서 CI secret·개발자 자격증명에 접근할 수 있습니다. lockfile과 캐시에서 4.6.6 사용 여부를 찾고 격리된 환경에서 재빌드하며, 당시 노출 가능한 npm·GitHub·클라우드 토큰을 회전하고 lifecycle script 차단 및 egress 정책을 적용해야 합니다.
- **패키지 게시일:** 4.6.6 — 2026-10-11, 4.6.7 — 2026-10-12
- **원문:** [GitHub — Zod 4.6.6 변경 내역](https://github.com/colinhacks/zod/commit/d821685ea6732436fcdf786a81d076958471e467)

### Google DevSite, 클라이언트 쿠키의 signing key 재사용으로 인증 없는 RCE

보안 연구자 Simon Koeck은 Google 개발자 사이트의 Flask session cookie 안에 pickle 직렬화된 OAuth client secret이 평문으로 들어 있고, 같은 값이 cookie signing key로도 쓰인 점을 연결해 임의 session을 위조했다고 공개했습니다. 연구자에 따르면 이 체인은 7개 Google domain에서 인증 없이 원격 코드 실행으로 이어졌으며 8월 6일 신고, 10월 7일 수정됐고 Google VRP가 9만 달러 보상을 결정했습니다.

- **실무상 중요성:** 서명은 암호화가 아니며, 클라이언트가 가진 값으로 서명 키를 유도하거나 pickle 같은 실행 가능한 형식을 신뢰 경계 밖에 두면 여러 방어가 한 번에 무너집니다. OAuth 상태는 서버 측 opaque reference로 유지하고, 서비스별 고엔트로피 secret 분리·회전과 허용 return URL 검증을 점검해야 합니다.
- **공개일:** 2026-10-12
- **원문:** [Simon Koeck — How I Found a $90,000 Remote Code Execution Vulnerability in Google](https://simonkoeck.com/writeups/google-devsite-flask-session-pickle-rce)

## 오픈소스

### PS2 게임을 WebAssembly로 정적 재컴파일하는 `PS2 Web Recomp` 공개

PS2 Web Recomp는 Emotion Engine 기계어를 C++로 ahead-of-time 변환한 뒤 WebAssembly로 컴파일하고, PS2 운영체제·하드웨어를 재구현해 WebGPU로 그리는 MIT 라이선스 프로젝트입니다. 개발자는 Gran Turismo 4가 통합 GPU 노트북의 Chrome에서 2배 해상도·50fps, God of War II가 기본 해상도·60fps로 동작했다고 보고했으며, 현재 검증된 게임은 두 개뿐입니다. 저장소는 게임 데이터 없이 도구만 제공하고 사용자가 소유한 디스크 이미지를 로컬에서 변환하도록 안내합니다.

- **실무상 중요성:** 대규모 legacy binary를 브라우저로 옮길 때 정적 재컴파일, worker·SharedArrayBuffer, WebGPU compute, HTTP Range 요청을 결합한 구체적 사례입니다. 일반 웹 제품에 응용할 때는 cross-origin isolation header, GPU별 호환성, 저작권이 있는 생성 산출물의 배포 금지와 fallback 성능을 함께 고려해야 합니다.
- **공개일:** 2026-10-12
- **원문:** [GitHub — snuri00/ps2-web-recomp](https://github.com/snuri00/ps2-web-recomp)
