# 2026-11-23 AI·IT 개발 뉴스

최근 24시간의 공식 발표·릴리스와 공개 기술 토론을 우선하고, 중요한 검증 가능 소식이 적은 영역은 72시간까지 넓혔습니다. 같은 사건은 합쳤으며 공급자 주장과 preview·canary 기능은 안정판과 구분했습니다.

## AI Agent·개발 도구

### Agent Session Insights, coding-agent 세션을 근거 연결 보고서로 재생

Microsoft CTO Mark Russinovich가 공개한 Agent Session Insights는 Copilot CLI, Claude Code, Codex, Cursor와 Replit 대화 기록을 오프라인 HTML·PDF 보고서로 바꿉니다. 메시지와 분석 근거, 모델별 token·비용, 시간축을 함께 보여주며 `--noagent`로 추가 모델 호출 없이 계측·재생할 수 있습니다.

- **중요한 이유:** agent 생산성을 감으로 평가하지 않고 session evidence와 비용으로 회고할 수 있습니다. 다만 원본 log에는 credential·개인 대화·local path가 있을 수 있으므로 공유 전 redaction과 접근통제가 필요합니다.
- **공개일:** 2026-11-23 KST
- **원문:** [GitHub](https://github.com/markrussinovich/agent-session-insights)

### OpenAgentCore, OpenAI Agents API 호환 self-hosted runtime 공개

MiniMax가 OpenAI SDK의 base URL만 바꿔 Codex·Claude Code·MiniMax Code session을 자체 machine과 model에서 실행하는 OpenAgentCore를 공개했습니다. sandbox provider, workspace filesystem, harness와 model provider를 교체 가능한 protocol로 분리하고 idle compute와 persistent workspace를 지원합니다.

- **중요한 이유:** coding-agent control plane을 사내에 둘 선택지가 생기지만 API 호환성이 동작·보안 호환성을 뜻하지는 않습니다. sandbox 탈출, tenant 격리, secret 주입, egress와 작업 취소를 별도 검증해야 합니다.
- **공개일:** 2026-11-23 KST
- **원문:** [GitHub](https://github.com/MiniMax-AI/OpenAgentCore)

### Claude Code 2.1.330, enterprise 로그인·runner 관측성과 동시성 수정

Claude Code 2.1.330은 Enterprise Admin Console 조직 로그인, self-hosted runner 시작 directory와 registration·first-session metric을 추가했습니다. 긴 대화 compact 후 정지, 여러 process의 setting 저장 손실, 다른 session이 쓰는 worktree 삭제와 subagent MCP server 조기 종료 등 동시성 문제도 수정했습니다.

- **중요한 이유:** 여러 agent가 같은 repository·설정·MCP를 공유하는 CI 환경의 data loss와 hang 위험을 줄입니다. upgrade 전 worktree 격리, plugin allowlist와 조직 policy 상속을 staging runner에서 확인해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [GitHub Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.330)

### Amazon Transcribe, request-response형 동기 transcription API 제공

`TranscribeAudio`는 최대 25MB inline 또는 500MB S3 audio를 한 요청으로 받아 최대 1시간 분량 transcript를 같은 response로 돌려줍니다. 한국어를 포함한 여러 언어, word timestamp, speaker·channel 식별, custom vocabulary와 PII redaction을 지원합니다.

- **중요한 이유:** 상담 clip·agent assist에서 job polling을 없앨 수 있지만 긴 HTTP 요청의 timeout·재시도 중복, audio PII 보관, 25MB/1시간 제한과 지역별 redaction 지원을 설계에 반영해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-transcribe-sync-api/)

## 보안·플랫폼

### Google, 공격자의 multi-agent 침투·n-day 자동화를 실제 관측

Google Threat Intelligence Group과 Mandiant는 ARTEX·CAIRN·PentAGI 같은 agentic penetration framework가 실제 침투의 여러 단계를 자동화하고, patch differential analysis로 n-day 취약점을 빠르게 무기화하는 흐름을 관측했다고 밝혔습니다. 탈취한 LLM credential·cloud resource를 underground proxy로 재판매하는 LLMJacking과 coding-assistant 설정을 악용한 supply-chain 시도도 보고했습니다.

- **중요한 이유:** 취약점 공개에서 exploit까지의 시간이 짧아지므로 internet-facing asset patch SLA와 credential anomaly 탐지를 줄여야 합니다. agent config·MCP·skill 파일도 executable supply chain으로 취급해 서명·review·egress 통제를 적용해야 합니다.
- **발표일:** 2026-11-23 KST
- **원문:** [Google Cloud / GTIG](https://cloud.google.com/blog/topics/threat-intelligence/agentic-threat-activity-crosses-a-significant-threshold)

### GL.iNet cloud 원격관리 취약점 악용…일부 router·KVM malware 감염

GL.iNet은 cloud remote-management 취약점으로 unauthorized party가 일부 router와 KVM에 malware를 설치했다고 공지했습니다. 공격 경로는 차단됐지만 기존 감염은 자동 제거되지 않으며, process에서 정확한 indicator `crond -i /tmp/.log`를 확인하고 감염 시 factory reset 또는 해당 KVM security beta를 적용하라고 안내했습니다.

- **중요한 이유:** remote KVM 침해는 연결된 운영 server까지 이어질 수 있습니다. 최신 stable security firmware를 적용하고 감염 장비의 cloud credential·SSH key를 회전하며 연결 host의 계정·startup task와 network activity도 조사해야 합니다.
- **발표일:** 2026-11-21 KST, stable 보안 firmware 예정일 2026-11-22
- **원문:** [GL.iNet Security Notice](https://www.gl-inet.com/en-us/blogs/blog/glinet-security-notice-2026-11-20)

## 데이터·클라우드·인프라

### Amazon MSK, Apache Kafka 4.2 지원

MSK Standard broker가 Kafka 4.2를 지원합니다. production-ready Queues for Kafka로 같은 topic partition을 여러 consumer가 병렬 처리할 수 있고, Eligible Leader Replicas와 새 consumer·Streams rebalance protocol도 포함됩니다.

- **중요한 이유:** 주문 작업 queue의 병렬성을 높일 수 있지만 기존 consumer-group 의미와 delivery ordering이 달라질 수 있습니다. rolling upgrade 전에 client 호환성, partition별 순서, duplicate 처리와 rebalance latency를 시험해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-msk-standard-version-42/)

### Aurora MySQL 8.4.12 GA, CVE·bug fix 반영

Aurora MySQL-Compatible Edition 8.4가 MySQL 8.4.12를 지원합니다. AWS는 이전 MySQL version의 CVE와 bug fix를 받기 위해 minor upgrade를 권고하며, Organizations Upgrade Rollout Policy로 cluster를 단계적으로 올릴 수 있다고 설명했습니다.

- **중요한 이유:** 보안 patch를 늦추지 않되 query plan, connector, replication과 zero-downtime 기대를 lower-priority cluster에서 먼저 검증해야 합니다. automatic minor upgrade window와 rollback snapshot도 함께 점검해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-aurora-mysql-8412-available/)

## 아키텍처·API·커머스

### EventBridge Custom event bus, managed Webhook Events 지원

EventBridge enhanced Custom event bus가 SaaS·agent webhook을 받을 managed HTTPS URL을 만들고 HMAC signature, static token 또는 basic authentication으로 검증합니다. 수신 event는 subscriber가 일반 event처럼 filter·delivery하며 webhook 자체 추가 요금 없이 custom-event ingress로 과금됩니다.

- **중요한 이유:** 배송 상태·결제 provider callback용 API Gateway·Lambda를 줄일 수 있습니다. signature replay window, secret rotation, payload schema, duplicate·out-of-order event와 dead-letter 처리는 여전히 application 책임입니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-eventbridge-webhook-events)

### AWS Pricing Calculator, 최대 500 usage line 즉시 견적 API

`GetUsageLinesEstimatedCost`는 estimate를 저장하지 않고 한 요청의 최대 500개 usage line에 대한 항목별·총비용을 반환합니다. public On-Demand, discount 반영, Savings Plans·Reserved Instances까지 반영한 세 rate type을 선택할 수 있습니다.

- **중요한 이유:** IaC review나 coding agent가 배포 전 비용 guardrail을 걸 수 있습니다. estimate는 invoice 보장이 아니므로 region·data transfer·tax 누락을 표시하고 승인 기준과 실제 Cost Explorer drift를 함께 관리해야 합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-pricing-calculator-api/)

### AWS Payments API, 잔액·invoice·payment method 상태 자동 조회

새 Billing and Cost Management API는 account balance, due·past-due invoice, payment·credit memo 적용 내역과 payment instrument 활성 상태를 SDK·CLI에서 조회합니다. `GetAccountBalance`, `ListFinancialRecords`, `GetPaymentInstrument` 등을 accounts-payable workflow와 연결할 수 있습니다.

- **중요한 이유:** cloud invoice reconciliation과 연체 감지를 자동화할 수 있지만 finance data에 대한 IAM 최소권한, account별 reconciliation key, pagination·eventual consistency와 변경 감사가 필요합니다.
- **발표일:** 2026-11-21 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-billing-cost-management-apis-payment-status/)

### TanStack Start, React·Solid용 full-stack framework로 type-safe server 경계 제공

TanStack Start는 TanStack Router 위에 SSR, streaming, server function과 full-document caching을 결합한 React·Solid full-stack framework입니다. HN 등 개발자 커뮤니티에서 framework 선택과 server/client 경계에 대한 논의가 이어졌으며 공식 문서가 현재 기능 범위를 제공합니다.

- **중요한 이유:** end-to-end type safety와 routing 통합은 생산성을 높일 수 있지만 deployment adapter, cache invalidation, server-function authorization과 ecosystem maturity를 production 채택 전에 검증해야 합니다.
- **확인일:** 2026-11-23 KST
- **원문:** [TanStack Start 공식 문서](https://tanstack.com/start/latest)
