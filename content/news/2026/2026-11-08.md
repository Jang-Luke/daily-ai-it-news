# 2026-11-08 AI·IT 개발 뉴스

최근 24시간의 공개 자료를 우선하고, 주말 동안 공식 발표가 적은 영역은 72시간까지 확장했습니다. 커뮤니티에서 발견한 이슈는 원문·공식 저장소를 함께 확인했으며, 같은 사건의 재보도는 합쳤습니다.

### Claude Code 권한 설정 파일이 1,122개 공개 저장소에서 비밀정보를 노출했다는 조사

Apiiro는 Claude Code의 “다시 묻지 않음” 선택으로 생성되는 로컬 권한 파일에 명령 문자열과 비밀정보가 남고, 이 파일이 공개 GitHub 저장소 1,122곳에서 발견됐다고 보고했습니다. 이는 보안업체의 조사 결과이며 개별 저장소의 실제 악용 여부까지 뜻하지는 않지만, agent 설정 파일도 credential과 같은 수준으로 취급해야 한다는 신호입니다.

- **중요한 이유:** `.gitignore`만 믿지 말고 pre-commit secret scan, 저장소 history 검사, 노출 key 회전을 함께 수행해야 합니다.
- **발표·보도일:** 2026-11-07
- **원문:** [Apiiro — Coding agents leaking secrets through “Don’t Ask Again”](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)

### GitLab, Git 호환성을 유지한 agent용 소스관리 구상 공개

- **중요한 이유:** agent가 동시에 만드는 대량 변경은 사람 중심 pull request 모델의 충돌·검토 병목을 키우므로 provenance와 승인 경계를 먼저 설계해야 합니다.

### MaxxBench, coding-agent benchmark 점수의 재현성 검증 제안

MaxxBench는 DeepSWE 계열 평가에서 제출된 점수만 비교하지 말고 실행 trace, patch 유효성, 환경과 독립 재검증을 함께 보자는 문제를 제기했습니다. 이는 연구팀의 평가 제안이며 표준으로 확정된 것은 아니지만, 내부 agent 도입 평가에서도 단일 leaderboard 점수의 한계를 환기합니다.

- **중요한 이유:** 성공률 외에 비용, 재시도 수, test 오염, 사람이 수정한 비율과 재현 가능한 실행 기록을 같이 측정해야 합니다.

## 개발자 체크포인트

- agent 권한 파일과 실행 transcript를 secret scan 대상에 넣고 이미 노출된 token은 history 정리와 별개로 즉시 회전하세요.
- AI package·model에는 checksum, signature, SBOM·provenance 검증과 격리된 실행 환경을 공급망 gate로 두세요.
- agent 도입 평가는 leaderboard 점수뿐 아니라 재현 가능한 trace, 비용, 사람 수정률과 regression을 기록하세요.
- 주문·결제 feature flag는 SDK 장애 시 안전한 기본값, kill switch 승인자와 stale flag 제거 기한을 명시하세요.
- frontend·cluster update는 stable/canary를 구분하고 checkout·payment 회귀 test와 rollback 조건을 먼저 검증하세요.
