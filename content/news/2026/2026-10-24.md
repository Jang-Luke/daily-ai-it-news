### GitHub Apps의 enterprise 설치·관리 API 정식 출시

GitHub Apps를 enterprise에 설치하고 repository policy·ruleset, 2FA, verified domain, IP allowlist와 access restriction 등을 API로 관리하는 기능이 GA가 됐습니다. GitHub는 classic PAT를 더 많은 enterprise 자동화에서 최소 권한의 App credential로 대체할 수 있다고 설명합니다.

- **실무상 중요성:** 장기 PAT를 App installation token으로 바꾸면 회수와 권한 범위 관리가 쉬워집니다. 마이그레이션 때 각 workflow에 필요한 permission만 부여하고 GraphQL·REST 동작을 staging enterprise에서 검증하세요.
- **발표일:** 2026-10-23
- **원문:** [GitHub Changelog — Enterprise installations for GitHub Apps generally available](https://github.blog/changelog/2026-10-23-enterprise-installations-for-github-apps-generally-available)

## 웹·클라우드·인프라

### Cloudflare, 자동 chunk 기반 Origin Range Requests 출시

Cloudflare는 client의 byte-range 요청을 cache의 고정 chunk 경계에 맞춰 origin에서 가져오고 필요한 byte만 반환하는 Origin Range Requests를 모든 plan에 제공했습니다. Cloudflare의 R2 측정에서는 p99 TTFB가 약 절반으로 줄었고 후속 개선으로 tiered-cache traffic이 약 6% 감소했으며, 사용자는 Cache Rule에서 기능을 켤 수 있습니다.

- **실무상 중요성:** 영상, 대형 artifact와 resumable download의 origin 대역폭을 줄일 수 있지만 `206 Partial Content`, cache key, 압축·서명 URL과 미정렬 range의 동작을 실제 파일 크기 분포로 시험해야 합니다.
- **발표일:** 2026-10-23
- **원문:** [Cloudflare — Origin Range Requests](https://blog.cloudflare.com/origin-range-requests/)

### Cloudflare, post-quantum 지역 제한 key manager closed beta

Cloudflare가 Data Localization Suite용 PQ GeoKey Manager를 closed beta로 공개했습니다. ML-KEM-768과 X25519의 hybrid 보호를 사용하고, 지역별 root key가 허용 지역 밖으로 나가지 않도록 하며 key가 없거나 잘못되면 복호화를 fail closed하는 구조입니다. GA는 2027년 1분기로 계획돼 있습니다.

- **실무상 중요성:** 규제 데이터의 지역 제한과 harvest-now-decrypt-later 위협을 함께 다루는 선택지가 생겼습니다. 다만 key 사용 지역만으로 routing·log·backup의 전체 data residency가 보장되지는 않으므로 별도 통제를 검증해야 합니다.
- **발표일:** 2026-10-23
- **원문:** [Cloudflare — Bringing post-quantum cryptography to geographically fenced key management](https://blog.cloudflare.com/post-quantum-geo-key-manager/)
