- **중요한 이유:** AI API·coding agent를 핵심 업무에 붙인 팀은 모델 품질만이 아니라 공급사의 compute 조달, 가격·계약 변화와 vendor concentration을 운영 위험에 넣어야 합니다. IPO 문서의 전망과 시장 규모는 보장된 결과가 아닙니다.
- **공시일:** 2026-10-26

## 클라우드·보안

### Cloudflare Workers AI GLM-5.3에서 요청 간 KV cache 데이터 노출

Cloudflare는 8월 27일부터 9월 9일까지 GLM-5.3 Workers AI에서 다른 고객 요청의 데이터가 섞일 수 있었고 총 155개 응답이 영향을 받았다고 공개했습니다. 1,048,576-token context에 비해 prefill GPU KV pool은 681,280 token에 불과했고, SGLang의 거부 경로가 stale cache page를 남긴 복합 원인이었습니다. 회사는 고의 악용 증거를 찾지 못했으며 다른 Workers AI 모델은 영향받지 않았다고 밝혔습니다.

- **중요한 이유:** shared inference 환경은 application log만으로 tenant isolation을 보장할 수 없습니다. 운영자는 영향 기간의 장문 prompt를 확인하고 secret·개인정보가 있었다면 회전·통지 범위를 평가하며, self-hosted SGLang도 reject path와 전송 token 수 검증 patch를 적용해야 합니다.
- **발표일:** 2026-10-26
- **원문:** [Cloudflare — Cross-request KV cache exposure and remediation](https://blog.cloudflare.com/kv-cache-exposure-remediation/)

### Broccoli2Shell: Brotli C decoder의 out-of-bounds write로 RCE 가능

CVE-2026-111497은 Google Brotli C decoder 1.0.3~1.2.0의 block 전환 오류로, 조작된 압축 데이터를 처리할 때 내부 buffer 바깥에 쓸 수 있는 취약점입니다. 공개 기술 분석은 Node.js 22/24/26, Python `Brotli`·`brotlicffi`, vendored C decoder를 사용하는 여러 도구를 영향 범위로 제시하며, 실행 중 process와 container는 package 설치 뒤에도 restart·rebuild가 필요하다고 설명합니다.

- **중요한 이유:** 외부 URL fetch, webhook, crawler, Brotli request body와 압축 archive는 간접 노출 경로입니다. SBOM에서 동적 library뿐 아니라 vendored·정적 copy를 찾고 Node 26.12.1/24.22.1/22.23.4 또는 수정된 Brotli 계열로 올린 뒤 재배포해야 합니다.
- **공개·갱신일:** 2026-10-26
- **원문:** [Broccoli2Shell — CVE-2026-111497 technical advisory](https://broccoli2shell.com/)

### Apple, 침해된 eMudhra 중간 CA 차단 범위와 macOS CLI 예외 안내

Apple은 private key가 침해된 eMudhra 중간 CA 8개 중 TLS용 6개가 임의 site 인증서를 만들 위험이 있다고 설명하고, 10월 19일부터 관련 certificate를 framework 수준에서 자동 차단했다고 밝혔습니다. 다만 macOS의 `curl`, `git`, `python3`, `openssl` 등 일부 command-line tool은 `/etc/ssl/cert.pem`을 사용해 향후 업데이트 전까지 certificate를 받아들일 수 있어 관리자용 임시 조치를 별도로 안내했습니다.

- **중요한 이유:** browser에서 차단됐다는 사실을 CI runner와 developer CLI까지 안전하다는 의미로 해석하면 안 됩니다. macOS fleet은 Apple 업데이트 상태, 별도 trust store를 가진 도구와 TLS inspection 영향을 함께 확인해야 합니다.
- **발표일:** 2026-10-26
- **원문:** [Apple Support — About the compromised eMudhra intermediate CAs](https://support.apple.com/en-us/149555)

## 언어·오픈소스 생태계

### C++26 초안, ISO DIS 표결에서 부결

공개된 표결 분석에 따르면 C++26 draft는 P-member 찬성 12/20(60%)과 전체 반대 9/22(41%)로 승인 조건을 충족하지 못했습니다. reflection, `std::execution`, library hardening과 contracts가 들어 있는 초안 전체가 승인되지 않았으며, 공식 comment 보고서와 후속 일정은 아직 확정되지 않았습니다.

- **중요한 이유:** compiler vendor의 experimental C++26 구현을 바로 장기 호환 contract로 삼지 말아야 합니다. 표준 확정 전에는 feature-test macro, compiler별 CI와 fallback을 유지하고 특히 contracts 문법·동작의 후속 변경을 추적해야 합니다.
- **분석 게시일:** 2026-10-25
- **원문:** [Train IT — The result of the C++26 DIS ballot](https://train-it.eu/blog/cpp26-contracts-the-ballot-result/)

### Pharo 14, 개발 도구와 VM 현대화

Pharo 14는 Mission Control·Pulse, 새 Method Browser·Settings Browser 등 Spec 기반 도구 전환을 확대하고 refactoring command를 통합 registry 뒤의 driver architecture로 옮겼습니다. VM에는 frame·stack 관리 통합, RISC-V JIT, GC·old-space allocation 개선과 cross-platform build 현대화가 포함됐습니다. release 주기도 봄에서 가을로 바뀌었습니다.

- **중요한 이유:** live image와 plugin을 운영하는 팀은 IDE 기능뿐 아니라 VM·GC·build 변화의 image 호환성과 native extension을 점검해야 합니다. RISC-V 지원은 교육·embedded 실험의 선택지를 넓힙니다.
- **발표일:** 2026-10-26
- **원문:** [Pharo — Pharo 14 Released](https://pharo.org/news/2026-10-26-Pharo14Release.html)

### Stalwart 1.0, mail·calendar·contacts 서버의 첫 안정판 선언

Stalwart 프로젝트는 mail server 1.0을 발표하며 protocol parser, storage round trip, cache와 full-text search를 광범위하게 재설계했다고 밝혔습니다. RocksDB·PostgreSQL·MySQL·FoundationDB·SQLite별 tuning과 phrase search, 대형 account용 cache tier 등이 포함됐으며 “가장 빠르다”는 표현은 프로젝트 자체 benchmark 주장입니다.

- **중요한 이유:** self-hosted mail은 throughput만 아니라 data migration, IMAP/JMAP 호환, spam·backup·restore와 장애 복구가 핵심입니다. 1.0 도입 전 production mailbox 복제본으로 index rebuild와 rollback을 검증해야 합니다.
- **발표일:** 2026-10-26
- **원문:** [Stalwart Labs — Stalwart v1.0](https://stalw.art/blog/stalwart-1-0/)
