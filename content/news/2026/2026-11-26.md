# 2026-11-26 AI·IT 개발 뉴스

최근 24시간의 공식 발표·릴리스와 공개 기술 토론을 우선하고, 검증 가능한 중요 소식은 72시간까지 넓혔습니다. 공급자의 성능 수치는 독립 검증과 구분했으며 같은 사건은 합쳤습니다.

## AI Agent·개발 도구

### Lambda durable functions, 격리 MicroVM 오케스트레이션 개발자 프리뷰

AWS가 durable function에서 Lambda MicroVM 작업과 세션 수명주기를 다루는 확장을 공개했습니다. 체크포인트·자동 재시도를 갖춘 최대 1년짜리 workflow에서 agent 생성 코드, CI 작업, 보안 scanner를 VM 수준으로 격리해 실행할 수 있습니다.

- **중요한 이유:** 임의 코드 실행 agent의 control plane을 serverless workflow로 단순화할 수 있지만 개발자 프리뷰입니다. sandbox escape 가정, egress·secret 제한, 재시도 시 중복 실행과 상태 보존 비용을 별도로 검증해야 합니다.
- **발표일:** 2026-11-26 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/lambda-durable-microvm/)

### Amazon Transcribe Turbo, 음성 agent용 의미 기반 turn-taking 프리뷰

차세대 speech-to-text 모델 Turbo가 streaming·batch로 공개됐습니다. AWS는 기존 production model 대비 streaming 단어 오류율이 영어 약 14%, 지원 유럽 언어 약 11% 낮아졌다고 주장하며, 영어 streaming에 의미 기반 발화 종료 판단과 끼어들기 감지를 추가했습니다.

- **중요한 이유:** 고정 silence timeout보다 자연스러운 대화가 가능하지만 수치는 공급자 평가이고 streaming preview는 우선 Ohio 리전입니다. 한국어 batch 지원과 영어 voice workflow를 실제 소음·억양·결제정보 마스킹 조건에서 따로 시험해야 합니다.
- **발표일:** 2026-11-25 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/transcribe-turbo-preview/)

### Google, 검증 가능한 사회적 추론 평가 framework 공개

Google Research는 숨은 동기를 가진 agent와 사용자 persona의 상호작용을 구성하고, assistant가 사용자의 주관적 서술만으로 동기를 추론하게 하는 multi-agent 평가 framework와 dataset을 공개했습니다. 평가에서는 사용자 framing에 민감하고, 사람보다 많은 세부정보를 요구하며, clarification question을 충분히 활용하지 못하는 경향이 나타났습니다.

- **중요한 이유:** 상담·고객지원 agent가 한쪽 설명을 사실로 확정하는 실패를 재현 가능한 ground truth로 측정할 수 있습니다. 이 결과를 production 전체 성능으로 일반화하지 말고, 주문 분쟁·상담 dataset에 귀속 표현과 확인 질문 평가를 추가하는 출발점으로 써야 합니다.
- **발표일:** 2026-11-26 KST
- **원문:** [Google Research](https://research.google/blog/verifiable-social-reasoning-for-llm-assistants/)

### Microsoft AI, 대규모 reinforcement-learning infrastructure 설계 공유

Microsoft AI가 대규모 RL 학습을 위해 rollout·training 자원을 분리하고 heterogeneous workload를 운영하는 infrastructure 경험을 공개했습니다. 공개 기술 토론에서는 agent 학습의 throughput뿐 아니라 failure recovery와 scheduling이 핵심 관심사로 부상했습니다.

- **중요한 이유:** agent RL은 GPU 사용률 하나보다 rollout 지연, stale policy, checkpoint와 재현성 관리가 전체 효율을 좌우합니다. 자체 구축 전 workload별 queue·artifact lineage·실패 격리를 먼저 계측해야 합니다.
- **발표일:** 2026-11-26 KST
- **원문:** [Microsoft AI](https://microsoft.ai/news/rl-infrastructure-at-microsoft-ai/)

### AWS IAM, federation·Roles Anywhere까지 trusted identity propagation 확대

- **중요한 이유:** 여러 role을 거친 agent·CI 요청의 실제 주체를 추적하기 쉬워집니다. 전달 claim을 그대로 신뢰하지 말고 issuer·audience·수명·risk score 생성 주체를 검증하며, 기존 session tag 정책과 충돌을 점검해야 합니다.
- **발표일:** 2026-11-25 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-iam/)

### Defang, production credential·주요 database 복사 사고 공개

Defang은 공격자가 11월 12일 production credential과 main database 사본을 복사했다고 공개하고 노출 범위, 대응 조치와 사용자 권고를 게시했습니다. 이는 사업자의 사고 보고이며 각 사용자는 자신의 token·integration log로 실제 영향을 확인해야 합니다.

- **중요한 이유:** deployment platform breach는 연결된 cloud account와 CI secret으로 확산될 수 있습니다. Defang 사용 조직은 공지의 rotation 지침, cloud audit log, 비정상 배포·image와 장기 token을 우선 점검해야 합니다.
- **발표일:** 2026-11-26 KST
