# 2026-11-19 AI·IT 개발 뉴스

최근 24시간의 공식 발표와 릴리스를 우선했습니다. preview·canary와 공급자 성능 주장은 안정판 및 독립 검증 결과와 구분했습니다.

## AI Agent·개발 도구

### Copilot, Supabase·Box·Calendly 등 8개 검증 MCP 연결 추가

GitHub가 Copilot에서 사용할 수 있는 GitHub-verified MCP server 연결을 8개 더 공개 preview로 열었습니다. 외부 서비스의 검색·콘텐츠·업무 데이터를 agent가 직접 다룰 수 있지만, 연결마다 OAuth scope와 쓰기 권한을 따로 검토해야 합니다.

- **중요한 이유:** agent의 실무 범위가 넓어지는 만큼 prompt injection과 과도한 권한이 SaaS 데이터 변경으로 이어지는 경로도 늘어납니다.
- **발표일:** 2026-11-19 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-18-connect-supabase-box-calendly-and-more-to-copilot)

### Gemini 4 Neon, GitHub Copilot에서 일반 제공

GitHub가 agentic coding, 다단계 tool use와 knowledge work를 겨냥한 Google Gemini 4 Neon을 Copilot에 일반 제공했습니다. GitHub가 전한 품질 특성은 공급자 설명이므로 repository별 task, latency와 비용을 같은 평가셋에서 비교해야 합니다.

- **중요한 이유:** coding agent 모델 선택지가 늘었지만 모델별 데이터 처리 정책과 재현성, 조직 허용목록 관리가 함께 필요합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-18-gemini-4-neon-in-github-copilot)

### Copilot 팀 customization 일반 제공

GitHub 조직의 team 단위로 공통 Copilot plugin과 설정을 공유하는 team customizations가 일반 제공됐습니다. 개인별 반복 설정을 줄일 수 있으나 중앙 설정 변경이 많은 개발자에게 동시에 영향을 주므로 versioning과 변경 승인이 필요합니다.

- **중요한 이유:** agent 도구 구성을 platform engineering 자산으로 표준화할 수 있지만 잘못된 plugin·instruction의 blast radius도 커집니다.
- **발표일:** 2026-11-19 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-18-customize-github-copilot-for-your-team)

### Amazon OpenSearch Memory 일반 제공

AWS가 agent interaction을 검색 가능한 event로 저장하고 session 사이에서 관련 기억을 검색하는 serverless OpenSearch Memory를 일반 제공했습니다. 기억에서 파생한 정보는 원 대화와 다를 수 있으며 장기 보존은 개인정보·삭제·tenant 격리 정책의 대상입니다.

- **중요한 이유:** 자체 vector·event memory 계층 운영을 줄일 수 있지만 retrieval 품질, 보존기간과 잘못된 기억의 수정 경로를 설계해야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-memory-generally-available/)

### AWS Glue ETL, Spark 최적화 agent 제공

AWS Glue ETL이 완료된 Spark job의 telemetry를 분석해 비용 또는 성능 목표에 맞는 configuration 변경과 근거를 제안하는 최적화 agent를 도입했습니다. 제안은 운영 데이터의 정확성이나 business SLA까지 자동 보증하지 않습니다.

- **중요한 이유:** skew·spill·과잉 capacity 탐색을 단축할 수 있지만 실제 적용 전 대표 데이터로 결과 정확도와 비용을 재측정해야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/apache-spark-aws-glue-etl/)

## 보안·플랫폼

### GitHub Team, security risk assessment 자동 실행

GitHub Team 조직에서 노출 credential과 code risk를 찾는 무료 security risk assessment가 자동 실행됩니다. 관리자와 security manager가 결과를 볼 수 있지만 자동 진단은 secret rotation, code review와 기존 scanner를 대체하지 않습니다.

- **중요한 이유:** 별도 실행 없이 초기 보안 가시성을 얻지만 false positive·negative를 고려한 triage 책임과 접근권한 통제가 필요합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-18-security-risk-assessments-run-automatically-on-github-team)

### SageMaker AI, cross-Region inference routing 지원

SageMaker AI가 한 region의 accelerator capacity 부족이나 endpoint 이상 때 다른 region·AWS account의 endpoint로 inference 요청을 보낼 수 있게 했습니다. data residency, inter-region latency·전송비와 failover 중 중복 요청은 별도 검증 대상입니다.

- **중요한 이유:** AI service 가용성을 높일 수 있지만 주문·결제 보조 모델은 timeout, idempotency와 지역별 개인정보 정책을 함께 맞춰야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/sagemaker-cross-region-routing/)

### CloudFront origin mTLS, WebSocket·gRPC 지원

CloudFront와 AWS region의 application origin 사이 mTLS가 WebSocket과 gRPC traffic까지 지원됩니다. 장기 연결에도 origin 인증을 적용할 수 있지만 certificate rotation, connection draining과 실패 시 관측성을 시험해야 합니다.

- **중요한 이유:** 실시간 API의 origin 위조 방어를 강화하면서 edge 뒤의 persistent connection에도 일관된 신뢰 경계를 만들 수 있습니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-cloudfront-origin-mtls-websockets-grpc/)

### Amazon Cognito, point-in-time recovery 지원

Cognito user pool을 이전 시점으로 복원하는 PITR이 추가됐습니다. 기존 자체 export·restore보다 identifier와 password continuity를 유지하기 쉬워지지만 복원 시점 이후의 가입·변경을 어떻게 reconciliation할지는 application 책임입니다.

- **중요한 이유:** identity 장애 복구가 단순해지지만 복원 rehearsal, RPO/RTO와 감사 log 보존을 실제 tenant에서 검증해야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-point-in-time-recovery/)

### Lambda, customer-managed runtime 제공

Lambda Event Functions에서 runtime을 function 배포와 분리된 독립 resource로 관리하고 platform team이 내용·update·접근·lifecycle을 중앙 통제할 수 있게 됐습니다. 공유 runtime의 빠른 patch가 가능하지만 잘못된 update가 여러 function에 동시에 전파될 수 있습니다.

- **중요한 이유:** 언어 runtime과 공통 agent를 조직 표준으로 운영할 수 있으므로 canary rollout, pinning과 rollback 계약이 중요해집니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-customer-managed-runtimes/)

### Lambda Managed Instances, GPU Event Functions 지원

Lambda Managed Instances가 EC2 G-series를 이용한 GPU 가속 Event Functions를 지원합니다. AWS가 driver·framework·scaling 운영을 줄인다고 설명하지만 cold start, concurrency, GPU memory 격리와 비용은 workload별 측정이 필요합니다.

- **중요한 이유:** inference·media 처리의 serverless 선택지가 늘지만 지속 부하에는 전용 endpoint 대비 경제성을 반드시 비교해야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-lambda-gpu-managed-instances/)

## 웹·데이터베이스·아키텍처

### CloudFront Functions, request 중 network call 지원

CloudFront Functions가 요청 처리 중 외부 응답을 받아 personalization·authorization 등의 판단에 사용할 수 있게 됐습니다. 기존 Lambda@Edge나 origin 호출을 줄일 수 있지만 외부 dependency가 edge latency와 availability에 직접 들어옵니다.

- **중요한 이유:** edge logic이 강력해지는 대신 짧은 timeout, fail-closed/open 정책, cache와 SSRF 방어를 명확히 해야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/cloudfront-functions-network-calls/)

### RDS for MySQL 9.7.4 LTS 지원

Amazon RDS for MySQL이 MySQL 9.7 LTS 계열의 9.7.4를 지원합니다. Replication Applier Metrics, JSON Duality Views와 Hypergraph Optimizer가 포함되며 major upgrade이므로 connector·SQL mode·optimizer plan 호환성을 확인해야 합니다.

- **중요한 이유:** replication 진단과 JSON 활용이 개선되지만 주문·결제 query plan 변화는 shadow traffic과 rollback 가능한 migration으로 검증해야 합니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-rds-mysql-974-available/)

### RDS, snapshot 기반 volume 초기화 가속

RDS의 PITR, read replica 생성과 Single-AZ→Multi-AZ 전환에서 snapshot block을 더 빨리 초기화해 처음부터 예측 가능한 성능을 제공하는 기능이 발표됐습니다. 실제 복구시간은 database 크기·region·workload에 따라 재측정해야 합니다.

- **중요한 이유:** 장애복구 직후의 lazy loading 성능 저하를 줄일 수 있어 RTO 산정이 현실적이지만 정기 복구 훈련을 대신하지는 않습니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-rds-fast-storage-volume-initialization/)

### Aurora DSQL, database 내부 audit logging 지원

Aurora DSQL이 connection 기록을 넘어 DDL·DML·DCL·SELECT statement를 database 내부에서 capture하는 managed audit logging을 지원합니다. SQL text에는 개인정보나 민감한 literal이 들어갈 수 있어 destination 권한, masking과 retention 비용을 검토해야 합니다.

- **중요한 이유:** 규제 환경의 행위 추적이 쉬워지지만 audit log 자체가 새로운 민감 데이터 저장소가 됩니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-aurora-dsql-audit-logging/)

### CloudFront standard log, CMCD와 추가 field 지원

CloudFront standard logging이 기존 real-time log에서만 보던 CMCD와 추가 access field를 S3, CloudWatch Logs, Data Firehose로 전달할 수 있게 됐습니다. streaming media와 cache 분석에 유용하지만 field 추가에 따른 개인정보·저장비용을 확인해야 합니다.

- **중요한 이유:** 별도 real-time stream 없이 client playback·edge 요청 신호를 분석할 수 있어 CDN 품질 진단 비용을 낮출 수 있습니다.
- **발표일:** 2026-11-19 KST
- **원문:** [AWS](https://aws.amazon.com/about-aws/whats-new/2026/11/cloudfront-standard-logging-cmcd-fields)
