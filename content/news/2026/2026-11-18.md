# 2026-11-18 AI·IT 개발 뉴스

최근 24시간의 공식 발표와 릴리스를 우선했습니다. 공급자가 제시한 성능·절감 수치는 독립 검증 결과가 아니며, preview와 canary는 안정판과 구분했습니다.

## AI Agent·개발 도구

### GPT-6.2 Astra·Sol, GitHub Copilot과 Amazon Bedrock에 동시 제공

GitHub와 AWS가 OpenAI GPT-6.2 Astra와 Sol의 일반 제공을 각각 발표했습니다. Astra는 복잡한 추론·코딩·코드리뷰와 저지연 모드, Sol은 반복적이고 검증 가능한 대량 agent workflow의 비용·속도를 강조하지만, 실제 품질은 조직의 repository와 평가셋으로 검증해야 합니다.

- **중요한 이유:** 같은 모델을 IDE와 cloud runtime에서 선택할 수 있어 개발·운영 경계를 잇기 쉬워지는 대신, 데이터 처리 위치와 비용·latency 정책을 별도로 관리해야 합니다.
- **발표일:** 2026-11-18 KST
- **원문:** [GitHub Changelog](https://github.blog/changelog/2026-11-17-openais-gpt-6-2-astra-and-gpt-6-2-sol-now-available), [AWS — Bedrock 제공](https://aws.amazon.com/about-aws/whats-new/2026/11/openai-gpt-6.2-astra-sol-amazon-bedrock/)

### GitHub Copilot Fusion, 지원 surface·모델·공개 benchmark 확대

GitHub가 여러 모델을 조합하는 Copilot Fusion의 이용 범위와 모델 선택지를 넓히고 Terminal-Bench 공개 leaderboard 결과를 공개했습니다. 공개 benchmark는 비교 단서일 뿐 조직별 codebase, tool permission과 사람의 검토 비용까지 대표하지는 않습니다.

- **중요한 이유:** model routing을 공급자에게 맡길수록 평균 성능은 개선될 수 있지만 실행 재현성과 모델별 규정 준수 추적은 어려워질 수 있습니다.
- **발표일:** 2026-11-18 KST
- **원문:** [GitHub Changelog — Copilot Fusion updates](https://github.blog/changelog/2026-11-17-github-copilot-fusion-updates-more-availability-benchmarks-and-models)

### GitHub Copilot app, Azure DevOps·GHES·브라우저 작업으로 연결 범위 확대

GitHub Copilot app이 Azure DevOps repository, GitHub Enterprise Server instance와 browser 작업을 지원하는 Microsoft Ignite 변경을 발표했습니다. 연결 대상마다 OAuth·enterprise policy·browser action 권한이 달라질 수 있으므로 최소 권한과 audit trail을 먼저 확인해야 합니다.

- **중요한 이유:** agent가 여러 SCM과 browser를 넘나들면 생산성은 높아지지만 credential·민감 repository·외부 페이지 사이의 신뢰 경계가 넓어집니다.
- **발표일:** 2026-11-18 KST
- **원문:** [GitHub Changelog — Copilot app Ignite releases](https://github.blog/changelog/2026-11-17-github-copilot-app-microsoft-ignite-releases)

### GitHub Copilot Evals 공개 preview

GitHub가 prompt, model, skill과 tool 변경이 Copilot 결과에 미치는 영향을 측정하는 Copilot Evals를 공개 preview로 내놓았습니다. preview의 지표와 제공 범위는 변할 수 있으므로 production gate에 바로 연결하기보다 대표 task와 사람 평가의 일치도를 먼저 보정해야 합니다.

- **중요한 이유:** agent 설정 변경을 감으로 배포하지 않고 회귀와 품질 변화를 반복 측정할 기반이 생깁니다.
- **발표일:** 2026-11-18 KST
- **원문:** [GitHub Changelog — Copilot Evals](https://github.blog/changelog/2026-11-17-github-copilot-evals-is-now-in-public-preview)

### Bedrock AgentCore Memory, 10년 보존과 전체 session 요약 지원

AWS는 AgentCore Memory의 short-term event 보존기간을 최대 10년으로 늘리고, summary strategy에 session 전체 요약을 자동 생성하는 기능을 발표했습니다. 장기 보존은 편의 기능이 아니라 개인정보·삭제요청·법적 보존과 저장비용 정책의 대상이며, 요약은 원 대화의 완전한 증거가 아닙니다.

- **중요한 이유:** 장기 실행 agent의 연속성과 감사 가능성이 높아지지만 목적 제한, tenant 격리와 retention 삭제 절차를 더 엄격히 설계해야 합니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — 10-year retention](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-bedrock-agentcore-memory-10-year-retention), [AWS — full session summaries](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-bedrock-agentcore-memory-full-session-summaries)

### EMR Serverless, 근거를 제시하는 Spark 최적화 agent 도입

AWS는 완료된 Spark job의 configuration·log·telemetry를 분석해 비용 또는 성능 목표에 맞는 설정 변경과 근거를 제안하는 최적화 agent를 발표했습니다. 제안 계산은 deterministic recommendation engine을 사용하며 단일 실행이나 known-good baseline과 비교할 수 있습니다.

- **중요한 이유:** skew, spill, 낮은 parallelism과 과잉 capacity를 빨리 찾을 수 있지만 추천 적용 전 데이터 정확성·완료시간·비용을 재현 test로 확인해야 합니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — Apache Spark Optimization Agent](https://aws.amazon.com/about-aws/whats-new/2026/11/apache-spark-optimization-agent/)

## 보안·플랫폼

### Copilot code review, adaptive effort·secret detection 추가

GitHub는 pull request 난이도에 따라 review depth를 조정하는 adaptive effort와 secret detection 등 Copilot code review 변경을 발표했습니다. 자동 리뷰는 보조 신호이므로 비밀 탐지 결과와 논리 오류 판단을 기존 secret scanner, test와 사람 승인 대신 사용해서는 안 됩니다.

- **중요한 이유:** 단순 PR과 위험한 PR에 검토 자원을 다르게 배분하고 credential 유출을 더 일찍 발견할 수 있습니다.
- **발표일:** 2026-11-18 KST
- **원문:** [GitHub Changelog — Copilot code review](https://github.blog/changelog/2026-11-17-copilot-code-review-adaptive-effort-secret-detection-and-more)

### AWS Security Hub, software·사용량으로 중요도 추론하고 GCP까지 통합

Security Hub가 tag와 이름뿐 아니라 설치 software와 resource usage를 사용해 resource criticality를 추론하고, GCP VM·Artifact Registry·Cloud Run·identity의 posture·취약점도 한 화면에서 관리할 수 있게 됐습니다. 자동 중요도는 business dependency를 완전히 알 수 없으므로 수동 tier와 예외 검증이 필요합니다.

- **중요한 이유:** tag가 불완전한 multi-cloud 환경에서 중요한 노출을 먼저 볼 수 있지만 잘못된 우선순위가 핵심 결제·주문 자산을 가리지 않도록 해야 합니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — resource criticality](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-resource-criticality/), [AWS — GCP support](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-gcp/)

### IAM Access Troubleshooter, access denied의 authorization context 제공

AWS IAM은 지원 service의 access denied 응답에 식별자를 넣고, 평가된 policy와 authorization context를 조회해 거부 원인을 추적하는 Access Troubleshooter를 발표했습니다. 진단 정보 자체가 권한 구조를 드러낼 수 있으므로 조회 권한과 audit를 제한해야 합니다.

- **중요한 이유:** 무작정 policy를 넓혀 문제를 푸는 관행을 줄이고 최소 권한을 유지한 채 denial 원인을 찾기 쉬워집니다.
- **발표일:** 2026-11-17 KST
- **원문:** [AWS — IAM Access Troubleshooter](https://aws.amazon.com/about-aws/whats-new/2026/11/iam-access-troubleshooter/)

### Amazon ECR, private registry용 global authentication token 지원

ECR이 같은 AWS partition의 여러 region에서 쓸 수 있는 global authentication token을 지원합니다. 기본 유효기간은 12시간이고 최소 5분까지 줄일 수 있으며 기존 regional token도 계속 동작합니다.

- **중요한 이유:** multi-region image proxy의 credential refresh를 단순화하지만 token 하나의 노출 범위가 넓어지므로 짧은 TTL, partition 경계와 pull/push 권한을 검토해야 합니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — ECR global authentication tokens](https://aws.amazon.com/about-aws/whats-new/2026/11/global-authentication-amazon-ecr)

### AWS Config, 공급자가 갱신하는 managed conformance pack 제공

AWS Config가 PCI DSS·SOC 2 같은 framework에 맞춘 managed conformance pack을 제공하고 새 rule이나 framework 개정에 따라 배포된 pack을 자동 갱신합니다. 자동 업데이트는 운영 부담을 줄이지만 rule 변화가 예고 없이 compliance 결과와 비용을 바꿀 수 있어 change monitoring이 필요합니다.

- **중요한 이유:** 여러 region에서 동일한 보안 기준을 유지하기 쉬워지지만 자동 평가 통과가 실제 통제의 완전성을 증명하지는 않습니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — managed conformance packs](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-config-managed-conformance-packs)

## 데이터·클라우드·아키텍처

EMR 8.2가 LTS release로 공개되며 Spark 4.1.3, Iceberg 1.11.0과 Delta Lake 4.2.0으로 올라갔습니다. S3 conditional write를 이용한 여러 cluster의 Delta table 동시 write, Iceberg materialized view 증분 refresh와 Lake Formation까지 end-user identity 전달도 포함합니다.

- **중요한 이유:** lakehouse 동시성·governance를 개선하지만 format·connector·UDF 호환성과 rollback 경로를 staging에서 확인해야 합니다.

### DynamoDB, ElastiCache Serverless for Valkey 기반 write-through cache 제공

AWS는 자주 읽는 DynamoDB 데이터를 ElastiCache Serverless for Valkey로 cache해 sub-millisecond read를 제공하는 기능을 일반 공개했습니다. 선택한 table·API와 TTL을 설정하며 application IAM policy를 적용하고, 별도 기능요금 없이 cache와 DynamoDB 사용료가 발생합니다.

- **중요한 이유:** application code 변경 없이 read latency를 줄일 수 있지만 주문·재고처럼 최신성이 중요한 데이터는 consistency와 invalidation 동작을 부하·장애 test로 검증해야 합니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — DynamoDB caching](https://aws.amazon.com/about-aws/whats-new/2026/11/dynamodb-caching-elasticache/)

### API Gateway REST API, native JWT authorizer 지원

API Gateway REST API가 OIDC·OAuth 2.0 issuer의 JWT signature, issuer, audience, expiry, claim과 method별 scope를 gateway에서 직접 검증할 수 있게 됐습니다. Lambda authorizer 운영을 줄일 수 있지만 algorithm allowlist, key rotation, clock skew와 multi-issuer 혼동을 설정에서 확인해야 합니다.

- **중요한 이유:** web·mobile·machine-to-machine API의 인증 경로를 단순화하면서도 application 도달 전 일관된 token 검증을 적용할 수 있습니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — API Gateway JWT authorizers](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-api-gateway-rest-authorizers-jwt/)

### Aurora DSQL, 모든 성공 SQL의 statement statistics 제공

Aurora DSQL이 SQL별 실행 횟수, 시간, scan·return·변경 row와 DPU 사용량을 CloudWatch OTel metric으로 기록해 Database Insights에서 볼 수 있게 했습니다. sampling이 아니라 성공한 모든 statement를 측정하며 cluster별 opt-in과 CloudWatch 비용이 적용됩니다.

- **중요한 이유:** 고비용·고빈도 query를 정량적으로 찾기 쉬워지지만 normalized SQL과 telemetry 접근권한이 민감한 schema 정보를 노출하지 않도록 해야 합니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — Aurora DSQL statement statistics](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-dsql-statement-statistics/)

### AWS inter-region network, Multipath Resilience로 99.999% SLA 제공

AWS는 VPC cross-region peering, Transit Gateway와 Cloud WAN의 cross-region traffic에 Multipath Resilience를 적용해 99.999% SLA를 제시했습니다. payment 처리 등 중단 민감 workload를 예로 들지만 SLA는 application 가용성과 동일하지 않으므로 failover, timeout과 중복처리 설계는 계속 필요합니다.

- **중요한 이유:** multi-region 주문·결제망의 network 목표가 높아지지만 application-level idempotency와 data recovery 없이는 end-to-end 복원력이 완성되지 않습니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — cross-Region 99.999% SLA](https://aws.amazon.com/about-aws/whats-new/2026/11/vpc-tgw-cloudwan-99999-sla/)

### AWS Interconnect–Microsoft Azure multi-cloud 연결 일반 제공

AWS가 Azure와 private multi-cloud 연결을 구성하는 AWS Interconnect의 일반 제공을 발표했습니다. DIY global network의 복잡성을 줄인다는 공급자 설명이지만 region coverage, routing domain, encryption, egress 비용과 한쪽 cloud 장애 시 독립성을 검토해야 합니다.

- **중요한 이유:** 두 cloud 사이 data·service 연결을 표준화할 수 있으나 shared control plane과 비용구조가 새로운 의존성이 될 수 있습니다.
- **발표일:** 2026-11-18 KST
- **원문:** [AWS — Interconnect with Microsoft Azure](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-announces-AWS-interconnect-multicloud-azure-ga/)

- GPT-6.2와 Copilot Fusion 도입 전 repository별 평가셋으로 정확도·latency·비용·데이터 경계를 함께 측정하세요.
- agent memory를 장기 보존할 때 개인정보 삭제, tenant 격리, 법적 보존과 암호화 key 수명을 10년 설정과 맞추세요.
- ECR global token은 최소 TTL과 최소 pull/push scope를 사용하고 multi-region proxy의 credential 유출 반경을 시험하세요.
- DynamoDB cache는 상품·재고·주문 상태의 stale read 허용범위와 장애 시 direct fallback을 부하 test로 확인하세요.
- multi-region 결제 경로는 network SLA와 별개로 idempotency key, timeout, 재시도·보상 transaction과 reconciliation을 검증하세요.
