## 보안·플랫폼

### CISA, 실제 악용된 WordPress Core RCE 취약점 추가

CISA는 CVE-2026-119977을 11월 3일 Known Exploited Vulnerabilities에 추가했습니다. 예측 가능하고 웹에서 접근 가능한 upgrade staging 경로의 TOCTOU 경쟁 조건 때문에 full-package upgrade 중 인증 없는 서버 코드 실행이 가능하다는 설명입니다.

- **중요한 이유:** WordPress 운영자는 7.1.4 등 공급자 수정판 적용뿐 아니라 최근 upgrade 시점의 웹 로그·파일 변경을 조사해야 합니다.
- **목록 추가일:** 2026-11-03
- **원문:** [CISA KEV — CVE-2026-119977](https://www.cisa.gov/sites/default/files/feeds/known_exploited_vulnerabilities.json), [WordPress 7.1.4](https://wordpress.org/news/2026/10/wordpress-7-1-4/)

### Next.js 16.4.5, cache 격리 관련 보안 수정 배포

Vercel은 Next.js 16.4.5에 `use cache`와 `unstable_cache` 조합의 cross-tenant 정보 노출, root parameter 간 cache 누출, shared fallback shell cache poisoning 수정이 포함됐다고 밝혔습니다. multi-tenant 서비스는 단순 업그레이드 후에도 cache key 경계를 회귀 시험해야 합니다.

- **중요한 이유:** 사용자·tenant 입력이 cache key에서 빠지면 인증이 올바르더라도 다른 요청의 민감 정보가 재사용될 수 있습니다.
- **발표일:** 2026-11-03
- **원문:** [vercel/next.js v16.4.5](https://github.com/vercel/next.js/releases/tag/v16.4.5)

## 웹·클라우드·인프라·API

### Next.js canary, edge response와 cache 경계 수정 이어가

Next.js 16.5.0-canary.39는 edge response의 내부 middleware cookie header 제거, forwarded fetch의 압축 framing, binary argument cache key와 request parameter에 의한 shared shell poisoning 수정을 포함합니다. canary는 production 권장판이 아니므로 변경 내용을 확인하되 안정판 backport 여부를 추적해야 합니다.

- **중요한 이유:** CDN·edge·application cache가 겹치는 환경에서는 header stripping과 cache key 불변식이 tenant 격리의 일부입니다.
- **발표일:** 2026-11-03
- **원문:** [vercel/next.js v16.5.0-canary.39](https://github.com/vercel/next.js/releases/tag/v16.5.0-canary.39)

### Low-code API 관리, 편의성과 통제력 trade-off 재조명

TechTarget은 low-code API management가 onboarding과 정책 구성을 단순화하지만 복잡한 예외, 관측성, vendor lock-in과 rollback에서 제약이 생길 수 있다고 분석했습니다. 제품별 차이가 크므로 실제 traffic replay와 장애 전환 시험이 필요합니다.

- **중요한 이유:** 주문·결제 API는 화면 설정 편의보다 versioning, idempotency, 감사 로그와 configuration rollback을 계약으로 고정해야 합니다.

- **Next.js:** 16.4.5가 여러 cache 격리·poisoning 보안 문제를 수정했습니다. multi-tenant 배포는 긴급 업그레이드와 cache 회귀 시험이 필요합니다. ([공식 release](https://github.com/vercel/next.js/releases/tag/v16.4.5), 2026-11-03)
- **Redis:** 8.12 RC2가 공개됐으나 production용이 아닌 pre-release입니다. RedisSearch 통합을 staging에서 검증할 수 있습니다. ([공식 release](https://github.com/redis/redis/releases/tag/8.12-rc2), 2026-11-01)

## 개발자 체크포인트

- WordPress와 Next.js 자산을 긴급 inventory하고 수정판 적용 뒤 cache·파일 무결성과 접근 로그를 확인하세요.
- AI agent·IDE plugin에는 최소권한 credential, 사용자 승인, tool-call 감사와 회귀 평가를 적용하세요.
- 주문·결제 API cache key에 tenant·사용자·권한 context가 포함되는지, webhook과 재시도 idempotency를 시험하세요.
- 매장 OT·IoT를 결제망과 분리하고 vendor patch SLA와 비상 수동 운영 절차를 점검하세요.
- 급상승 오픈소스는 star가 아니라 license, maintainer, release provenance와 sandbox 검증으로 채택하세요.
